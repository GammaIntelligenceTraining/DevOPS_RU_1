# Модуль 6: Автоматизация на Bash и инфраструктурные скрипты — Шпаргалка по командам

Краткий справочник по синтаксису скриптов Bash, защитным директивам интерпретатора, условным операторам, управляющим конструкциям и промышленным паттернам идемпотентного развертывания.

---

## 1. Жизненный цикл скриптов и защитные директивы исполнения

В промышленных DevOps-окружениях скрипты автоматизации выполняются в неинтерактивном режиме внутри раннеров CI/CD, планировщиков cron или на этапах инициализации контейнеров Kubernetes. Защитные директивы гарантируют, что скрытые ошибки не перерастут в масштабные инфраструктурные аварии.

| Директива / Команда | Категория | Описание | Применение в продакшене (Когда и зачем) | Пример использования |
| :--- | :--- | :--- | :--- | :--- |
| `#!/bin/bash` | Шебанг | Инструкция ядру, определяющая бинарный файл интерпретатора. | Обязательна в первой строке каждого скрипта, чтобы вызов `execve()` запускал Bash, а не откатывался к системной оболочке по умолчанию (`/bin/sh` или Dash). | `#!/bin/bash` |
| `chmod +x <file.sh>` | Безопасность | Устанавливает бит права на исполнение (`x`) для файла скрипта. | Позволяет запускать скрипт напрямую (`./deploy.sh`) в пайплайнах деплоя без обязательного вызова через `bash <file>`. | `chmod +x /opt/scripts/deploy.sh` |
| `./<file.sh>` | Исполнение | Запускает скрипт как дочерний процесс в изолированной подоболочке. | Стандартный способ запуска, гарантирующий изоляцию локальных переменных и рабочей директории от родительского шелла. | `./provision.sh` |
| `bash -x <file.sh>` | Диагностика | Трассирует выполнение скрипта, выводя каждую команду с подставленными значениями. | Применяется при расследовании инцидентов и отладке пайплайнов для просмотра раскрытия переменных и выбора веток ветвления. | `bash -x ./onboard.sh dev_alex` |
| `source <file.sh>` или `. <file.sh>` | Исполнение | Выполняет команды скрипта в контексте текущей сессии оболочки. | Используется для импорта переменных окружения и секретов напрямую в активную сессию терминала. | `source /etc/environment.d/production.env` |
| `set -e` | Защита | Немедленно прерывает выполнение, если любая команда завершилась с ошибкой. | Предотвращает продолжение деплоя после неудачной миграции базы данных или сбоя скачивания пакета. | `set -e` |
| `set -u` | Защита | Считает обращение к неинициализированным переменным фатальной ошибкой. | Предотвращает катастрофические сбои вида `rm -rf /${DEPLOY_DIR}`, если переменная `DEPLOY_DIR` случайно не была задана. | `set -u` |
| `set -o pipefail` | Защита | Сохраняет ненулевой код возврата любой сбойной команды внутри конвейера. | Устраняет маскирование ошибок, когда сбойная первая команда (например, `mysqldump \| gzip`) возвращает 0 из-за успешности `gzip`. | `set -o pipefail` |
| `set -euo pipefail` | Защита | Объединяет все три защитные директивы в одну декларацию. | Стандартный заголовок любого продакшен-скрипта, исключающий неконтролируемые сбои. | `set -euo pipefail` |

## 2. Специальные переменные и подстановка параметров

Скрипты автоматизации используют специальные встроенные переменные оболочки для валидации входных аргументов, анализа процессов и установки безопасных значений по умолчанию.

| Токен | Область | Описание | Применение в продакшене (Когда и зачем) | Пример использования |
| :--- | :--- | :--- | :--- | :--- |
| `$0` | Специальная | Путь или имя запущенного файла скрипта. | Используется в справке и сообщениях об ошибках для вывода актуального имени скрипта без жесткого кодирования. | `echo "Использование: sudo $0 <cluster_name>"` |
| `$1, $2 ... $9` | Специальная | Позиционные входные аргументы, переданные скрипту или функции. | Прием динамических параметров инфраструктуры: имен пользователей, хостов, IP-адресов или сред развертывания. | `ENVIRONMENT="${1:-staging}"` |
| `$#` | Специальная | Целочисленное количество переданных аргументов командной строки. | Проверяется в начале скрипта для подтверждения передачи обязательных параметров перед запуском. | `if [ "$#" -ne 2 ]; then exit 1; fi` |
| `$@` | Специальная | Массив всех позиционных аргументов как отдельных строк в кавычках. | Безопасная итерация в циклах по списку целей (серверов, пакетов, файлов) с сохранением пробелов. | `for host in "$@"; do ssh "$host"; done` |
| `$$` | Специальная | Идентификатор процесса (PID) текущего экземпляра скрипта. | Запись в lock-файлы (`/var/run/script.pid`) для предотвращения параллельного запуска копий скрипта. | `echo "$$" > /var/run/app_worker.pid` |
| `$?` | Специальная | Код возврата (0–255) последней завершенной команды переднего плана. | Анализ статуса сразу после критической команды для ветвления логики и запуска автоматического отката. | `if [ "$?" -ne 0 ]; then rollback; fi` |
| `$EUID` | Окружение | Эффективный идентификатор пользователя процесса (0 для root). | Проверяется первым действием в скриптах администрирования для мгновенной остановки при запуске без sudo. | `[ "${EUID:-$(id -u)}" -eq 0 ] \|\| exit 1` |
| `$(command)` | Подоболочка | Захватывает стандартный вывод дочерней команды в переменную. | Получение динамических данных окружения: шлюза по умолчанию, внешнего IP, временной метки или версии ядра. | `GATEWAY=$(ip route show default \| awk '{print $3}')` |
| `${VAR:-default}`| Подстановка | Использует переменную, если она задана; иначе возвращает значение по умолчанию. | Задание параметров по умолчанию для конфигураций (тайм-аутов, номеров портов, названий сред). | `PORT="${PORT:-8080}"` |

## 3. Операторы проверки условий `[ ]`

Скрипты системного администрирования проверяют условия для оценки состояния файлов, числовых метрик и конфигурационных строк перед выполнением модификаций.

### Проверка параметров файловой системы
| Оператор | Проверяемое условие | Применение в продакшене (Когда и зачем) | Пример использования |
| :--- | :--- | :--- | :--- |
| `-f <path>` | Истина, если путь существует и указывает на регулярный файл. | Предварительная проверка наличия конфигурационных файлов, сертификатов SSL перед запуском службы. | `[ -f "/etc/nginx/sites-available/default" ]` |
| `-d <path>` | Истина, если путь существует и указывает на каталог. | Проверка точек монтирования, корневых каталогов веб-серверов или папок логов перед записью данных. | `[ -d "/var/www/html" ]` |
| `-x <path>` | Истина, если файл существует и имеет права на исполнение. | Проверка наличия обязательных бинарных зависимостей (`docker`, `curl`, `jq`) перед их вызовом. | `[ -x "/usr/bin/curl" ]` |
| `-s <path>` | Истина, если файл существует и его размер строго больше 0 байт. | Проверка того, что сформированные бэкапы или скачанные архивы не являются пустыми поврежденными файлами. | `[ -s "/backups/db_backup.sql" ]` |
| `-r <path>` | Истина, если файл существует и доступен для чтения текущему пользователю. | Проверка прав на чтение чувствительных файлов перед парсингом (ключей, конфигураций). | `[ -r "/etc/ssl/certs/server.crt" ]` |

### Числовые сравнения
| Оператор | Проверяемое условие | Применение в продакшене (Когда и зачем) | Пример использования |
| :--- | :--- | :--- | :--- |
| `-eq` | Истина, если числа равны. | Проверка ожидаемого HTTP-кода ответа (например, 200 OK) или нулевого количества ошибок. | `[ "$HTTP_STATUS" -eq 200 ]` |
| `-ne` | Истина, если числа не равны. | Проверка прав непривилегированного пользователя или фиксация ненулевого кода ошибки. | `[ "$EUID" -ne 0 ]` |
| `-gt` | Истина, если первое число строго больше второго. | Оповещение мониторинга при превышении порогов нагрузки на CPU, диск или числа сбоев. | `[ "$DISK_USAGE_PERCENT" -gt 90 ]` |
| `-lt` | Истина, если первое число строго меньше второго. | Ограничение количества попыток в циклах ожидания сервисов. | `[ "$RETRY_COUNT" -lt 5 ]` |
| `-ge` | Истина, если первое число больше или равно второму. | Проверка кворума нод в распределенном кластере или количества активных воркеров. | `[ "$ACTIVE_NODES" -ge 3 ]` |
| `-le` | Истина, если первое число меньше или равно второму. | Контроль лимитов параллельных подключений или ограничений ресурсов. | `[ "$CONNS" -le 1000 ]` |

### Строковые сравнения
| Оператор | Проверяемое условие | Применение в продакшене (Когда и зачем) | Пример использования |
| :--- | :--- | :--- | :--- |
| `==` | Истина, если строки идентичны. | Сравнение сред развертывания (`production` против `staging`) или имен ролей. | `[ "$DEPLOY_ENV" == "production" ]` |
| `!=` | Истина, если строки различаются. | Обнаружение отклонений конфигурации от эталона или нежелательных веток Git. | `[ "$CURRENT_BRANCH" != "main" ]` |
| `-z` | Истина, если строка пустая (длина 0). | Проверка отсутствия обязательных переменных окружения или аргументов CLI. | `[ -z "$DATABASE_URL" ]` |
| `-n` | Истина, если строка не пустая (длина > 0). | Подтверждение наличия токенов доступа, паролей или параметров конфигурации. | `[ -n "$API_TOKEN" ]` |

## 4. Управляющие конструкции и модульные паттерны

Структурированное управление потоком выполнения обеспечивает надежную проверку состояний, циклическую обработку и чистоту модульного кода.

Следующие фрагменты кода демонстрируют стандартное условное ветвление, сопоставление с шаблонами, циклы ожидания с повторами и модульные функции логирования:

Условное ветвление проверяет несколько условий с помощью операторов `if`, `elif` и `else`:
```bash
if [ "$EUID" -ne 0 ]; then
    echo "Ошибка: Требуются права суперпользователя." >&2
    exit 1
elif [ ! -f "/etc/nginx/nginx.conf" ]; then
    echo "Ошибка: Конфигурационный файл Nginx отсутствует." >&2
    exit 2
else
    echo "Предварительные проверки успешно пройдены."
fi
```

Конструкция `case` обеспечивает понятную маршрутизацию при выборе административных действий:
```bash
case "$ACTION" in
    start)
        systemctl start nginx
        ;;
    stop)
        systemctl stop nginx
        ;;
    reload|restart)
        nginx -t && systemctl reload nginx
        ;;
    *)
        echo "Использование: $0 {start|stop|reload}" >&2
        exit 1
        ;;
esac
```

Цикл ожидания `while` с ограничением числа попыток компенсирует сетевые задержки при запуске сервисов:
```bash
MAX_RETRIES=3
COUNT=0
while [ "$COUNT" -lt "$MAX_RETRIES" ]; do
    if curl -s -f http://127.0.0.1:80 &>/dev/null; then
        echo "Веб-сервис успешно отвечает."
        break
    fi
    COUNT=$((COUNT + 1))
    echo "Ожидание привязки сервиса к сокету... попытка $COUNT из $MAX_RETRIES"
    sleep 2
done
```

Модульная функция логирования формирует стандартизированный вывод с временными метками:
```bash
log_event() {
    local LEVEL="$1"
    local MESSAGE="$2"
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] [$LEVEL] $MESSAGE"
}
```

## 5. Паттерны идемпотентного развертывания в продакшене

В парадигме «Инфраструктура как код» (IaC) скрипты обязаны приводить систему к целевому состоянию независимо от того, запускаются ли они на чистом сервере или на работающей системе.

| Задача | Нестабильная императивная команда | Устойчивый идемпотентный паттерн | Инженерное обоснование для продакшена |
| :--- | :--- | :--- | :--- |
| **Создание каталога** | `mkdir /data/web` | `mkdir -p /data/web` | Флаг `-p` создает родительские пути и завершается с кодом 0 без ошибки, если каталог уже существует. |
| **Управление пользователями** | `useradd developer` | `id "developer" &>/dev/null \|\| useradd -m -s /bin/bash "developer"` | Проверяет базу пользователей; создает аккаунт только при его отсутствии, предотвращая ошибку с кодом 9. |
| **Установка пакетов** | `apt install -y nginx` | `dpkg -s nginx &>/dev/null \|\| (apt-get update -qq && apt-get install -y -qq nginx)` | Проверяет локальный статус пакета перед обновлением индексов и скачиванием трафика по сети. |
| **Правила фаервола** | `ufw allow 80/tcp` | `ufw status \| grep -q '80/tcp' \|\| ufw allow 80/tcp` | Исключает появление дублирующих правил в конфигурационных файлах `/etc/ufw/user.rules`. |
| **Активация фаервола** | `ufw enable` | `ufw --force enable` | Флаг `--force` подавляет интерактивные подтверждения терминала, блокирующие пайплайны CI/CD. |
| **Перезагрузка службы** | `systemctl restart nginx` | `nginx -t && systemctl reload nginx` | Предварительно валидирует синтаксис; выполняет мягкую перезагрузку без сброса активных сессий клиентов. |
| **Назначение владельца** | `chown user file` | `chown -R user:group /target/dir` | Рекурсивно приводит владельца к целевому состоянию без ошибок при совпадении текущих прав. |
| **Генерация ключей SSH** | `ssh-keygen` (интерактивный) | `[ -f "$KEY" ] \|\| ssh-keygen -t ed25519 -N "" -C "tag" -f "$KEY" -q` | Проверяет наличие ключа; генерирует пару без интерактивных запросов с пустой парольной фразой при отсутствии. |
| **Авторизация ключа SSH** | `cat key.pub >> authorized_keys` | `grep -q -F -f "$PUB" "$AUTH" 2>/dev/null \|\| cat "$PUB" >> "$AUTH"` | Проверяет наличие публичного ключа в файле, предотвращая появление дубликатов в `authorized_keys`. |
| **Контроль параллелизма** | `echo $$ > /tmp/lock` | `[ -f "$LOCK" ] && kill -0 "$(cat "$LOCK")" 2>/dev/null \|\| echo $$ > "$LOCK"` | Проверяет активность зафиксированного PID, корректно обрабатывая зависшие блокировки. |
