## Задание 1: Диспетчер команд управления веб-сервисом (`service_ctl.sh`)

### Сценарий
Системным администраторам часто требуется единая безопасная точка входа для управления критическими службами без необходимости запоминать низкоуровневые команды systemd или рисковать выполнением некорректных действий. Вам поручено написать скрипт-диспетчер `service_ctl.sh`, который принимает имя действия через аргумент командной строки и выполняет соответствующую операцию над службой Nginx.

### Технические требования
1. **Интерпретатор и переменные:**
   - Скрипт должен начинаться со стандартного шебанга Bash `#!/bin/bash`.
   - Сохраните имя управляемого сервиса в константную переменную `SERVICE_NAME="nginx"`.
   - Сохраните переданное действие из первого позиционного аргумента в переменную `ACTION="${1:-}"`.
2. **Проверка аргументов (конструкция `if`):**
   - С помощью условного оператора `if` и проверки `-z "$ACTION"` убедитесь, что аргумент передан.
   - Если аргумент отсутствует, выведите в поток стандартных ошибок `stderr` понятное руководство по запуску: `Использование: $0 {status|start|stop|restart}` и завершите работу с кодом `1`.
3. **Проверка прав суперпользователя (конструкция `if`):**
   - Для действий, изменяющих состояние службы (`start`, `stop`, `restart`), требуется запуск от имени `root` (проверка `$EUID -ne 0`).
   - Если запуск выполнен без привилегий суперпользователя, выведите в `stderr` сообщение об ошибке `Ошибка: для выполнения команды требуется запуск через sudo` и завершите работу с кодом `2`.
   - Для действия `status` права суперпользователя требоваться не должны.
4. **Обработка команд (конструкция `case`):**
   - Реализуйте блок `case "$ACTION" in ... esac` со следующими ветками:
     - `status`: выводит статус службы с помощью команды `/usr/bin/systemctl status "$SERVICE_NAME" --no-pager`.
     - `start`: запускает службу командой `/usr/bin/systemctl start "$SERVICE_NAME"` и выводит информационное сообщение об успешном старте.
     - `stop`: останавливает службу командой `/usr/bin/systemctl stop "$SERVICE_NAME"` и выводит информационное сообщение.
     - `restart`: перезапускает службу командой `/usr/bin/systemctl restart "$SERVICE_NAME"` и выводит информационное сообщение.
     - `*)`: для любого неизвестного действия выводит в `stderr` сообщение `Неизвестная команда: $ACTION` и завершает работу с кодом `3`.
5. **Коды завершения:**
   - При успешном выполнении разрешенной операции скрипт должен явно завершаться с кодом `0` (`exit 0`).

### Синтаксические примеры и подсказки

При проверке обязательных параметров скрипта удобно использовать безопасное чтение переменной с дефолтным значением и проверку на пустую строку:
```bash
CONFIG_MODE="${1:-}"

if [[ -z "$CONFIG_MODE" ]]; then
    echo "Ошибка: параметр не передан" >&2
    exit 1
fi
```

Для ограничения доступа к административным действиям проверяется переменная окружения `$EUID` (Effective User ID), которая у пользователя root всегда равна 0:
```bash
if [[ "$EUID" -ne 0 ]]; then
    echo "Ошибка: скрипт требует прав администратора" >&2
    exit 2
fi
```

Оператор `case` позволяет сопоставлять строковое значение с несколькими шаблонами и задавать действие по умолчанию через шаблон `*)`:
```bash
case "$COMMAND" in
    info)
        echo "Режим вывода информации"
        ;;
    apply)
        echo "Режим применения настроек"
        ;;
    *)
        echo "Неизвестный параметр: $COMMAND" >&2
        exit 3
        ;;
esac
```

### Порядок проверки решения
Для проверки скрипта выполните серию команд в терминале:

Запуск скрипта без аргументов для проверки валидации ввода:
```bash
./service_ctl.sh
```

Проверка кода возврата (должен быть равен 1):
```bash
echo $?
```

Проверка статуса службы без sudo (должна успешно отработать с кодом 0):
```bash
./service_ctl.sh status
```

Попытка перезапуска без sudo (должна прерваться с сообщением об ошибке и кодом 2):
```bash
./service_ctl.sh restart
```

Корректный перезапуск службы с правами root:
```bash
sudo ./service_ctl.sh restart
```

Передача неизвестного действия (должна завершиться с кодом 3):
```bash
./service_ctl.sh pause
```

### Требуемые результаты к сдаче
- Исходный код файла `service_ctl.sh`.
- Скриншот или лог терминала с выполнением всех шагов проверки.

## Задание 2: Пакетный аудит сетевых сервисов (`multi_check.sh`)

### Сценарий
Инженеру эксплуатации необходимо периодически проводить экспресс-аудит сетевых портов и прикладных эндпоинтов на локальном сервере, чтобы убедиться, что все обязательные компоненты системы активны, а нежелательные или закрытые порты не отвечают. Вам необходимо разработать скрипт `multi_check.sh`, который в цикле опрашивает список целевых портов, фиксирует результат каждой проверки и выводит итоговую статистику доступности.

### Технические требования
1. **Интерпретатор и инициализация:**
   - Шебанг `#!/bin/bash`.
   - Переменная `TARGET_HOST="127.0.0.1"`.
   - Переменная со списком портов для аудита: `PORTS="80 443 22 8080 3306"`.
   - Две числовые переменные-счетчика: `SUCCESS_COUNT=0` и `FAILED_COUNT=0`.
2. **Цикл опроса (конструкция `for`):**
   - Реализуйте цикл `for PORT in $PORTS; do ... done`.
   - Внутри каждой итерации выполните опрос веб-порта или сокета с помощью утилиты `curl` с коротким тайм-аутом подключения:
     `/usr/bin/curl --connect-timeout 2 -s -o /dev/null "http://${TARGET_HOST}:${PORT}"`
3. **Анализ результата опроса (конструкция `if`):**
   - С помощью анализа кода завершения последней команды (`$? -eq 0`):
     - Если код возврата равен `0`, выведите в консоль строку: `[ДОСТУПЕН] Порт ${PORT} на ${TARGET_HOST} успешно ответил`. Увеличьте значение переменной `SUCCESS_COUNT` на 1 с помощью арифметической конструкции `$((SUCCESS_COUNT + 1))`.
     - Если код возврата не равен `0`, выведите в консоль строку: `[НЕДОСТУПЕН] Порт ${PORT} на ${TARGET_HOST} не отвечает или закрыт`. Увеличьте `FAILED_COUNT` на 1 (`$((FAILED_COUNT + 1))`).
4. **Итоговый отчет:**
   - После завершения цикла выведите разделительную линию и сводный отчет:
     - Общее количество проверенных портов.
     - Количество успешных ответов (`$SUCCESS_COUNT`).
     - Количество недоступных портов (`$FAILED_COUNT`).
5. **Код возврата скрипта:**
   - Если `FAILED_COUNT` больше нуля, скрипт завершает работу с кодом `1`.
   - Если все порты успешно ответили (`FAILED_COUNT` равен 0), скрипт завершает работу с кодом `0`.

### Синтаксические примеры и подсказки

Цикл `for` позволяет последовательно обходить элементы, разделенные пробелами в строковой переменной:
```bash
NODES="app-01 app-02 db-01"

for NODE in $NODES; do
    echo "Обработка узла: $NODE"
done
```

Специальная переменная `$?` хранит код завершения последней выполненной команды, где нулевой код означает успешное завершение:
```bash
/usr/bin/curl --connect-timeout 2 -s -o /dev/null "http://127.0.0.1:80"

if [[ $? -eq 0 ]]; then
    echo "Сервис доступен"
else
    echo "Сбой подключения"
fi
```

Для увеличения числовых счетчиков в Bash используется конструкция арифметического вычисления `$(( ... ))`:
```bash
COUNTER=0
COUNTER=$((COUNTER + 1))
echo "Текущее значение: $COUNTER"
```

### Порядок проверки решения
Перед проверкой убедитесь, что Nginx запущен и слушает порт 80.

Запустите скрипт аудита портов:
```bash
chmod +x multi_check.sh
./multi_check.sh
```

Проверьте код завершения утилиты:
```bash
echo $?
```

В выводе терминала порт 80 должен отображаться со статусом `[ДОСТУПЕН]`, а остальные неактивные порты — со статусом `[НЕДОСТУПЕН]`. В итоговой сводке должно быть отражено точное число успешных и неуспешных проверок.

### Требуемые результаты к сдаче
- Исходный код файла `multi_check.sh`.
- Листинг вывода скрипта в терминале.

## Задание 3: Комплексный менеджер архивации логов (`log_archiver.sh`)

### Сценарий
В продакшен-окружении каталоги с логами серверов со временем переполняют дисковое пространство. Дежурному инженеру требуется инструмент автоматизации, позволяющий инспектировать каталог с логами, безопасно создавать архивные копии файлов журналов и при необходимости выполнять ротацию (очистку устаревших файлов). Напишите утилиту `log_archiver.sh`, объединяющую валидацию путей (`if`), перебор файлов журналов (`for`) и диспетчеризацию действий (`case`).

### Технические требования
1. **Параметры и переменные скрипта:**
   - Шебанг `#!/bin/bash`.
   - Переменная каталога с логами: `LOG_DIR="${1:-}"`.
   - Переменная команды режима работы: `ACTION="${2:-status}"`.
   - Переменная целевого каталога резервных копий: `BACKUP_DIR="/tmp/log_backups"`.
   - Переменная даты создания архива: `DATE_TAG="$(/usr/bin/date +%Y%m%d_%H%M%S)"`.
2. **Валидация аргументов и директории (конструкция `if`):**
   - Если первый аргумент пустой (`-z "$LOG_DIR"`), выведите в `stderr` справку: `Использование: $0 <путь_к_каталогу_логов> [status|archive|clean]` и завершите работу с кодом `1`.
   - Если указанный путь не существует или не является каталогом (`! -d "$LOG_DIR"`), выведите в `stderr` сообщение: `Ошибка: Каталог $LOG_DIR не существует` и завершите работу с кодом `2`.
3. **Диспетчеризация режимов работы (конструкция `case`):**
   Скрипт должен поддерживать три режима работы:
   - **Режим `status` (по умолчанию):**
     - Выводит заголовок инспекции каталога `$LOG_DIR`.
     - С помощью цикла `for LOG_FILE in "$LOG_DIR"/*.log; do ... done` проверяет каждый файл.
     - С помощью условного оператора `if [[ -f "$LOG_FILE" ]]` проверяет, действительно ли найден файл (защита от случая, когда маска `*.log` не нашла совпадений).
     - Выводит имя файла и его размер в читаемом формате (`ls -lh "$LOG_FILE"`).
     - Если файлов `.log` не найдено, выводит сообщение: `В каталоге нет файлов с расширением .log`.
   - **Режим `archive`:**
     - Создает каталог для бэкапов `$BACKUP_DIR`, если он отсутствует (проверка `if [[ ! -d "$BACKUP_DIR" ]]`).
     - Подсчитывает количество файлов `.log` перед архивацией с помощью цикла `for` и переменной-счетчика `LOG_COUNT`.
     - Если `LOG_COUNT` равен 0, сообщает об отсутствии файлов для архивации и завершает работу с кодом `0`.
     - Если файлы найдены, формирует сжатый архив:
       `/usr/bin/tar -czf "${BACKUP_DIR}/logs_${DATE_TAG}.tar.gz" -C "$LOG_DIR" .`
     - Выводит сообщение об успешном создании архива с указанием пути к архивному файлу и его размера.
   - **Режим `clean`:**
     - Требует подтверждения от пользователя через предварительную проверку или выводит предупреждение о начале очистки.
     - В цикле `for LOG_FILE in "$LOG_DIR"/*.log; do ... done` находит все файлы журналов.
     - С помощью `if [[ -f "$LOG_FILE" ]]` безопасно обнуляет содержимое каждого лога: `> "$LOG_FILE"` (сохраняя сам файл и его права, но освобождая занятое дисковое пространство).
     - Выводит строку `Журнал $LOG_FILE очищен` для каждого обработанного файла.
   - **Неизвестный режим (`*)`):**
     - Выводит сообщение в `stderr`: `Неизвестный режим: $ACTION. Допустимые значения: status, archive, clean` и завершает работу с кодом `3`.
4. **Завершение:**
   - При успешном завершении любого из штатных режимов скрипт возвращает код `0`.

### Синтаксические примеры и подсказки

Для предотвращения ошибок перед работой с путями необходимо убедиться, что целевая директория действительно существует на диске:
```bash
TARGET_PATH="/var/log/audit"

if [[ ! -d "$TARGET_PATH" ]]; then
    echo "Каталог не найден: $TARGET_PATH" >&2
    exit 1
fi
```

При переборе файлов по маске внутри цикла обязательно проверяется флаг `-f`, чтобы исключить ошибочную обработку самого текста маски при отсутствии совпадений:
```bash
for CONF_FILE in "$CONFIG_DIR"/*.conf; do
    if [[ -f "$CONF_FILE" ]]; then
        /usr/bin/ls -lh "$CONF_FILE"
    fi
done
```

Для освобождения дискового пространства без удаления самого файла и без смены его дескриптора используется оператор перенаправления вывода в файл:
```bash
TARGET_FILE="/tmp/sample.log"
> "$TARGET_FILE"
```
