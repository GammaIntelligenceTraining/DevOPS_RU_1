Краткая справочная таблица команд, рассмотренных в рамках **Модуля 3: Основы сетей и системные службы**.

## 1. Сетевые интерфейсы и конфигурация IP

| Команда | Описание | Применение в реальных сценариях DevOps |
| :--- | :--- | :--- |
| `ip link show` | Отображает сетевые интерфейсы, состояние 2-го уровня и MAC-адреса | Аудит сетевых интерфейсов: проверка физического или виртуального состояния линка (`UP`/`DOWN`) и размера MTU (`ip link show`) |
| `ip a` | Отображает назначенные IPv4 и IPv6 адреса с масками CIDR | Настройка интерфейсов: просмотр назначенных частных IP-адресов и префиксов подсетей (`ip a`) |
| `ip -br a` | Компактный однострочный список интерфейсов и IP-адресов | Написание скриптов автоматизации: получение понятного сопоставления интерфейсов и адресов без лишнего вывода (`ip -br a`) |
| `ip r` | Отображает таблицу маршрутизации ядра и шлюз по умолчанию | Диагностика маршрутизации: проверка маршрута по умолчанию (`default via <ip>`) для исходящего трафика кластера (`ip r`) |
| `hostname -I` | Выводит все внутренние IP-адреса хоста | Облачная инициализация: динамическое получение внутреннего IP виртуальной машины для конфигурационных шаблонов (`hostname -I`) |
| `curl -s ifconfig.me` | Запрос к внешнему сервису для определения публичного IP-адреса NAT | Проверка исходящего трафика: определение внешнего публичного IP, под которым машина обращается к внешним API или файрволам (`curl -s ifconfig.me`) |

## 2. Диагностика и разрешение DNS

| Команда | Описание | Применение в реальных сценариях DevOps |
| :--- | :--- | :--- |
| `dig [домен]` | Стандартный DNS-запрос (просмотр `ANSWER SECTION` и TTL) | Обнаружение сервисов: проверка A-записей домена и контроль срока жизни кэша TTL при обновлении DNS (`dig api.internal.local`) |
| `dig +short [домен]` | Возвращает только разрешенный IP-адрес | Автоматизация CI/CD: быстрое извлечение целевого IP для скриптов развертывания без необходимости парсинга заголовков (`dig +short db.prod.internal`) |
| `dig [домен] [тип]` | Запрос конкретного типа записи (A, AAAA, CNAME, MX, TXT) | Проверка домена: аудит записей аутентификации почты SPF/DKIM или маршрутов почтовых серверов (`dig company.com TXT`) |
| `dig @[резолвер] [домен]` | Запрос напрямую к указанному DNS-серверу | Диагностика резолверов: обход локального кэша системы и опрос публичного DNS-сервера напрямую для выявления сбоев кэширования (`dig @1.1.1.1 google.com`) |
| `dig [домен] +trace` | Трассировка полного пути от корневых серверов до авторитативных | Расследование делегирования: пошаговая проверка всей цепочки серверов от корня (`.`) до авторитативного сервера домена (`dig domain.com +trace`) |
| `dig -4 @[резолвер] [домен] +trace` | Трассировка с принудительным использованием IPv4 | Чистая трассировка: отключение попыток запроса IPv6 для устранения предупреждений о недоступности сети в IPv4-окружениях (`dig -4 @8.8.8.8 google.com +trace`) |
| `dig -x [ip]` | Выполнение обратного DNS-запроса (получение PTR-записи) | Анализ безопасности: проверка PTR-записей для подтверждения подлинности хоста отправляющей стороны (`dig -x 1.1.1.1`) |
| `host [домен]` | Краткая сводка по IP-адресам и почтовым серверам домена | Быстрая проверка: мгновенное получение базовой связки имени хоста с IP и MX записями (`host github.com`) |
| `nslookup [домен]` | Интерактивная утилита запросов к DNS | Кроссплатформенная диагностика: интерактивная проверка DNS, привычная администраторам Windows и Linux (`nslookup api.service.local`) |

## 3. Управление службами в Systemd (`systemctl`)

| Команда | Описание | Применение в реальных сценариях DevOps |
| :--- | :--- | :--- |
| `systemctl status [служба]` | Отображает состояние службы, PID, cgroups и последние логи | Мониторинг SRE: оценка работоспособности демона, его главного PID и трассировки падений в одной команде (`systemctl status nginx`) |
| `sudo systemctl start [служба]` | Немедленно запускает службу в оперативной памяти | Ввод в эксплуатацию: запуск процесса демона после установки пакета или обновления конфигурации (`sudo systemctl start nginx`) |
| `sudo systemctl stop [служба]` | Корректно останавливает дерево процессов службы | Плановое обслуживание: аккуратная остановка процессов перед миграцией баз данных или обновлением версий (`sudo systemctl stop nginx`) |
| `sudo systemctl restart [служба]`| Полный перезапуск службы (остановка и повторный запуск) | Восстановление и рестарт: перезапуск демона для очистки утечек памяти или применения обновленных бинарных файлов (`sudo systemctl restart nginx`) |
| `sudo systemctl reload [служба]` | Перечитывает конфигурацию службы без разрыва соединений | Обновление без простоя (Zero-Downtime): применение новых правил маршрутизации без сброса активных клиентских сессий (`sudo systemctl reload nginx`) |
| `sudo systemctl enable [служба]` | Включает автоматический запуск службы при загрузке системы | Сохранение при перезагрузке: создание символических ссылок в `/etc/systemd/system/` для запуска демонов при старте хоста (`sudo systemctl enable nginx`) |
| `sudo systemctl disable [служба]`| Отключает автозапуск службы при загрузке ОС | Вывод из эксплуатации: удаление симлинков автозапуска для устаревших или замененных служб (`sudo systemctl disable legacy_service`) |
| `sudo systemctl daemon-reload` | Перечитывает конфигурацию менеджера systemd | Регистрация unit-файлов: обновление кэша systemd после редактирования или создания пользовательских файлов служб (`sudo systemctl daemon-reload`) |
| `systemctl is-active [служба]` | Возвращает статус активности: active или inactive | Скрипты проверки жизнеспособности: получение кода возврата для проверок готовности подов и системных скриптов (`systemctl is-active nginx`) |
| `systemctl is-enabled [служба]`| Возвращает статус автозапуска: enabled или disabled | Аудит соответствия: проверка того, что критические службы безопасности добавлены в автозагрузку (`systemctl is-enabled ufw`) |
| `systemctl list-units --type=service --state=running` | Список всех активных служб в системе | Инвентаризация сервисов: проверка всех запущенных фоновых процессов демонов на сервере (`systemctl list-units --type=service`) |

## 4. Диагностика сокетов и портов (`ss`)

| Команда | Описание | Применение в реальных сценариях DevOps |
| :--- | :--- | :--- |
| `sudo ss -tunlp` | Показывает все слушающие TCP/UDP сокеты с именами процессов и PID | Аудит конфликтов портов: выявление занятых портов, прослушиваемых интерфейсов и PID процессов в ядре (`sudo ss -tunlp`) |
| `sudo ss -tunlp \| grep :[порт]`| Фильтрует слушающие сокеты по номеру порта | Проверка сервиса: подтверждение того, что веб-сервер привязан к `0.0.0.0:80`, а не только к локальному `127.0.0.1` (`sudo ss -tunlp \| grep :80`) |
| `ss -ta` | Отображает все сокеты TCP (слушающие и установленные) | Оценка нагрузки на сеть: просмотр всех активных клиентских TCP-соединений и их текущих состояний (`ss -ta`) |
| `ss -s` | Сводная статистика сокетов и буферов ядра | Мониторинг ресурсов ядра: контроль общего числа выделенных сетевых сокетов и буферов памяти TCP (`ss -s`) |

## 5. Инструменты веб-диагностики и связности

| Команда | Описание | Применение в реальных сценариях DevOps |
| :--- | :--- | :--- |
| `curl [url]` | Выполняет HTTP-запрос и выводит тело ответа | Проверка эндпоинтов: выполнение HTTP GET-запроса для валидации тела ответа приложения (`curl http://localhost/health`) |
| `curl -I [url]` | Запрашивает только заголовки HTTP (статус-код, тип сервера) | Проверка HTTP-статуса: анализ статус-кодов (`200 OK`, `404`, `502 Bad Gateway`) и заголовка Server без скачивания тела (`curl -I http://localhost`) |
| `curl -v [url]` | Подробный режим: вывод этапов DNS, TCP-рукопожатия и заголовков | Анализ протокола: подробное исследование процесса установки соединения, согласования шифров TLS и обмена заголовками (`curl -v https://api.service.internal`) |
| `curl -s [url]` | Тихий режим: скрывает индикатор прогресса (для скриптов) | Автоматизация CI/CD: чистое получение данных для скриптов мониторинга здоровья сервисов (`curl -s http://localhost/api/metrics`) |
| `curl -o [файл] [url]` | Сохраняет скачанные данные в файл с указанным именем | Получение артефактов: загрузка релизных архивов или файлов манифестов на диск (`curl -o app.tar.gz https://releases.internal/...`) |
| `curl -O [url]` | Скачивает файл с сохранением его исходного имени на сервере | Загрузка пакетов: скачивание файлов из удаленного репозитория с сохранением оригинального имени (`curl -O https://example.com/assets/logo.png`) |
| `curl -L [url]` | Автоматически следует по HTTP-редиректам (301/302) | Отслеживание перенаправлений: переход по цепочке редиректов HTTP-на-HTTPS до финального эндпоинта (`curl -L http://github.com`) |
| `curl -k [url]` | Небезопасный режим: разрешает соединения с самоподписанным SSL | Тестирование тестовых стендов: проверка эндпоинтов HTTPS со staging-сертификатами или внутренними центрами сертификации (`curl -k https://localhost:8443`) |
| `nc -zv [хост] [порт]` | Сканирование порта: проверка доступности TCP без передачи данных | Проверка 4-го транспортного уровня: проверка разрешения порта файрволом до отправки HTTP-запросов (`nc -zv 10.0.1.50 443`) |
| `ping -c [N] [хост]` | Проверка ICMP-связности с отправкой $N$ пакетов | Доступность 3-го уровня: базовая проверка доступности шлюза или удаленного сервера и замер задержки (`ping -c 4 8.8.8.8`) |
| `mtr -t [хост]` | Трассировка маршрута в реальном времени с анализом потерь на узлах | Анализ сетевого пути: выявление проблемного маршрутизатора или потерь пакетов на узлах глобальной сети (`mtr -t 8.8.8.8`) |

## 6. Журналирование и системные логи (`journalctl`)

| Команда | Описание | Применение в реальных сценариях DevOps |
| :--- | :--- | :--- |
| `sudo journalctl -u [служба]` | Отображает логи конкретного сервиса | Ретроспективный анализ: исследование логов запуска службы, истории аварийных завершений и предупреждений (`sudo journalctl -u nginx`) |
| `sudo journalctl -xeu [служба]`| Детальные логи падения с пояснениями из каталога ошибок в конце | Анализ инцидентов: мгновенный переход к последним записям падения с подсказками ядра системы (`sudo journalctl -xeu nginx`) |
| `sudo journalctl -u [служба] -f` | Потоковый вывод сообщений в режиме реального времени | Контроль развертывания: онлайн-мониторинг обращений и ошибок сервиса в момент деплоя нового релиза (`sudo journalctl -u nginx -f`) |
| `sudo journalctl -u [служба] -n [N]`| Выводит последние $N$ строк журнала | Быстрая выборка: просмотр последних 20 записей без блокировки терминала утилитой less (`sudo journalctl -u nginx -n 20 --no-pager`) |
| `sudo journalctl -u [служба] --since "[время]"` | Фильтрация логов по относительному временному окну | Локализация инцидента: изолирование логов, созданных строго во время проведения регламентных работ (`sudo journalctl -u nginx --since "15 min ago"`) |
