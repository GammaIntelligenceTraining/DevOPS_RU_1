# Домашнее задание к Модулю 3: Основы сетей и системные службы

Практическая работа по базовому сетевому администрированию Linux: выполнение DNS-запросов, анализ сетевых интерфейсов и таблицы маршрутизации, управление службами в Systemd, аудит сетевых сокетов через `ss` и клиентская веб-диагностика с анализом системных логов.

## Задание 1: Исследование DNS и трассировка запросов

Исследуйте систему доменных имен (DNS) с помощью утилит командной строки.

### Требования:
1. Выполните стандартный DNS-запрос для домена `wikipedia.org` и определите IPv4-адрес в секции ответов (`ANSWER SECTION`).
2. Запросите только чистый IP-адрес с использованием короткого формата вывода.
3. Определите почтовые серверы (MX-записи), обслуживающие домен `wikipedia.org`.
4. Выполните полную рекурсивную трассировку (`+trace`) для домена `wikipedia.org`, чтобы проследить путь запроса от корневых DNS-серверов (`.`) до авторитативных серверов.
5. Выполните обратный DNS-запрос (`-x`) для IP-адреса `1.1.1.1` и определите соответствующее ему доменное имя (PTR-запись).

<details>
<summary>Подсказки (нажмите, чтобы развернуть)</summary>

- Стандартный запрос: `dig <домен>`
- Короткий формат: `dig +short <домен>`
- Тип записи: `dig <домен> MX`
- Трассировка пути: `dig <домен> +trace`
- Обратный запрос: `dig -x <ip_адрес>`

</details>

**Что необходимо предоставить:**
- Вывод команды `dig +short wikipedia.org`.
- Вывод команды `dig wikipedia.org MX`.
- PTR-запись из вывода команды `dig -x 1.1.1.1`.

## Задание 2: Аудит сетевых интерфейсов и маршрутизации

Задокументируйте сетевую конфигурацию и основной шлюз маршрутизации вашей системы.

### Требования:
1. Выведите список всех активных сетевых интерфейсов и их физическое состояние с помощью команды `ip link`.
2. Отобразите назначенные внутренние IPv4-адреса и маски подсетей с помощью команды `ip a`.
3. Найдите петлевой интерфейс (loopback) и зафиксируйте его IP-адрес.
4. Изучите таблицу маршрутизации ядра с помощью команды `ip r` и найдите IP-адрес шлюза по умолчанию (Default Gateway).
5. Обратитесь к внешнему сервису и определите ваш внешний публичный IP-адрес.

<details>
<summary>Подсказки (нажмите, чтобы развернуть)</summary>

- Список интерфейсов: `ip link show`
- IP-адреса: `ip -br a` или `ip a`
- Таблица маршрутизации: `ip r` (ищите строку `default via ...`)
- Внешний IP: `curl -s ifconfig.me`

</details>

**Что необходимо предоставить:**
- Строку из вывода `ip a`, содержащую ваш основной IPv4-адрес (кроме петлевого интерфейса).
- Строку со шлюзом по умолчанию `default via` из вывода `ip r`.
- Значение публичного IP-адреса из команды `curl -s ifconfig.me`.

## Задание 3: Развертывание веб-службы под управлением Systemd

Установите и настройте веб-сервер Nginx под управлением менеджера служб Systemd.

### Требования:
1. Установите пакет веб-сервера `nginx` с помощью менеджера пакетов `apt`.
2. Проверьте исходный статус службы `nginx`, чтобы увидеть ее состояние по умолчанию.
3. Запустите службу `nginx` с помощью `systemctl`.
4. Настройте автоматический запуск `nginx` при старте операционной системы.
5. Проверьте подробный статус службы и убедитесь, что runtime-статус равен `active (running)`, а статус автозапуска равен `enabled`.

<details>
<summary>Подсказки (нажмите, чтобы развернуть)</summary>

- Установка: `sudo apt update && sudo apt install -y nginx`
- Статус службы: `systemctl status nginx`
- Запуск службы: `sudo systemctl start nginx`
- Включение автозапуска: `sudo systemctl enable nginx`
- Одновременный запуск и включение в автозапуск: `sudo systemctl enable --now nginx`

</details>

**Что необходимо предоставить:**
- Первые 6 строк вывода команды `systemctl status nginx`, содержащие поля `Loaded` и `Active`.

## Задание 4: Аудит сетевых сокетов и привязки портов

Убедитесь, что веб-сервер Nginx успешно занял сетевой порт и принимает входящие соединения.

### Требования:
1. Просмотрите все активные слушающие сокеты TCP на вашем сервере с помощью `ss`.
2. Отфильтруйте вывод так, чтобы отображался только сокет, слушающий порт 80.
3. Определите, слушает ли Nginx только локальный адрес (`127.0.0.1`) или все доступные интерфейсы (`0.0.0.0` или `*`).
4. Найдите идентификатор процесса (PID), открывшего сокет на 80-м порту.
5. Проверьте сетевую связность на транспортном уровне TCP с портом 80 с помощью утилиты `nc` (Netcat).

<details>
<summary>Подсказки (нажмите, чтобы развернуть)</summary>

- Просмотр слушающих портов: `sudo ss -tunlp`
- Фильтрация порта: `sudo ss -tunlp | grep :80`
- Сканирование порта через Netcat: `nc -zv localhost 80`

</details>

**Что необходимо предоставить:**
- Строку вывода команды `sudo ss -tunlp | grep :80`.
- Результат выполнения команды `nc -zv localhost 80`.

## Задание 5: Веб-диагностика и анализ логов доступа

Выполните тестовые клиентские HTTP-запросы и отследите их фиксацию в системном журнале.

### Требования:
1. Отправьте HTTP-запрос на `http://localhost` с помощью `curl` и убедитесь, что сервер возвращает стандартную страницу приветствия Nginx.
2. Запросите **только заголовки ответа** с помощью команды `curl -I http://localhost` и зафиксируйте код статуса HTTP и заголовок Server.
3. Выполните запрос в подробном режиме с помощью `curl -v http://localhost` и изучите этап TCP-рукопожатия (`Connected to localhost...`).
4. Запросите логи службы Nginx в systemd journal и найдите записи о выполненных клиентских подключениях.

<details>
<summary>Подсказки (нажмите, чтобы развернуть)</summary>

- Запрос HTML-страницы: `curl http://localhost`
- Запрос только заголовков: `curl -I http://localhost`
- Подробный режим: `curl -v http://localhost`
- Просмотр журнала службы: `sudo journalctl -u nginx -n 10 --no-pager`

</details>

**Что необходимо предоставить:**
- Заголовки ответа из вывода команды `curl -I http://localhost`.
- Последние 3 строки записей логов из команды `sudo journalctl -u nginx -n 3 --no-pager`.
