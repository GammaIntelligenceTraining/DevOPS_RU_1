## 1. Навигация по файловой системе, поиск, архивирование и перенаправление потоков

Исследование каталогов, фильтрация текста, создание архивов и управление дескрипторами стандартных потоков.

| Команда | Основные флаги и синтаксис | Применение в production (когда и зачем) | Пример использования |
| :--- | :--- | :--- | :--- |
| `ls` | `-la`<br>`-lh`<br>`-ld <путь>`<br>`-lhS` | Просмотр файлов и каталогов. `-a` отображает скрытые файлы; `-l` подробные метаданные; `-ld` метаданные каталога без входа внутрь; `-lhS` сортировка по размеру. | `ls -ld /var/www/html`<br>`ls -lhS /var/log` |
| `cd` | `-`<br>`~` | Навигация по файловой системе. `cd -` переключает между текущей и предыдущей рабочей директорией при администрировании нескольких путей. | `cd -` |
| `cat` | `-n`<br>`<< 'EOF'` | Вывод содержимого файла в терминал. `-n` нумерует строки. Конструкция `<< 'EOF'` позволяет безопасно создавать конфигурационные файлы. | `cat -n /etc/nginx/nginx.conf`<br>`cat << 'EOF' \| sudo tee file.conf` |
| `head` | `-n <строк>` | Вывод первых N строк файла или потока. Используется для обрезки длинного диагностического вывода команд `ps -eo` или дампов памяти. | `head -n 10 /var/log/syslog`<br>`ps -eo pid,comm \| head -n 5` |
| `tail` | `-n <строк>`<br>`-f` | Вывод последних N строк файла. Флаг `-f` отслеживает добавление новых строк в файл в реальном времени при отладке журналов. | `tail -f /var/log/nginx/error.log`<br>`tail -n 20 /tmp/db_sync.log` |
| `grep` | `-i`<br>`-v`<br>`-r`<br>`-n`<br>`-E` | Поиск строк по шаблону. `-i` без учета регистра; `-v` инверсия; `-r` рекурсивно; `-n` вывод номеров строк; `-E` расширенные регулярные выражения. | `grep -rnE "WARN\|CRITICAL" /var/log/`<br>`grep -v "healthcheck" access.log` |
| `find` | `-type f\|d`<br>`-name "<маска>"`<br>`-perm <маска>` | Поиск объектов в файловой системе в реальном времени по метаданным инодов. Поиск файлов логов или аудит небезопасных прав (`-perm 777`). | `find /var/log -type f -name "*.log"`<br>`find /tmp -type f -perm 777` |
| `tar` | `-czvf <архив>`<br>`-tzvf <архив>`<br>`-C <каталог>` | Работа со сжатыми архивами. `-c` создание; `-t` просмотр оглавления; `-z` сжатие gzip; `-v` подробный вывод; `-f` имя файла; `-C` смена рабочего каталога. | `tar -czvf /tmp/logs.tar.gz -C /var/log .`<br>`tar -tzvf /tmp/logs.tar.gz` |
| `tee` | `sudo tee <путь>`<br>`sudo tee -a <путь>` | Чтение stdin с одновременной записью в stdout и файл. Обходит ошибку перенаправления в защищенные файлы под sudo. Флаг `-a` дописывает в конец. | `echo "worker_threads=4" \| sudo tee /etc/app.conf`<br>`echo "debug=true" \| sudo tee -a /etc/app.conf` |

### Сравнение комбинаций флагов `ls`

| Вызов команды | Что отображается | Что скрыто / опущено | Применение в эксплуатации |
| :--- | :--- | :--- | :--- |
| `ls /var/www/html` | Только имена файлов в несколько колонок. | Скрытые dot-файлы, права, владельцы, размеры, даты. | Быстрая визуальная проверка наличия файлов. |
| `ls -la /var/www/html` | Подробный список всех записей, включая `.` и `..`. | Ничего. Раскрывает скрытые файлы и права каталогов. | Аудит безопасности и проверка владельцев файлов. |
| `ls -ld /var/www/html` | Подробные метаданные самого каталога. | Содержимое внутри каталога. | Проверка бита обхода каталога (`x`) и прав владельца. |
| `ls -lhS /var/log` | Подробный список, отсортированный по убыванию размера (`-S`). | Хронологический порядок файлов. | Поиск файлов, переполняющих дисковое пространство. |

### Матрица стандартных потоков и операторов перенаправления

| Оператор | Поток | Механика работы | Практический пример |
| :--- | :--- | :--- | :--- |
| `>` | `stdout` (1) | Перезаписывает целевой файл стандартным выводом команды. | `ps aux > /tmp/ps_snapshot.txt` |
| `>>` | `stdout` (1) | Дописывает стандартный вывод в конец целевого файла. | `date >> /tmp/deployment.log` |
| `2>` | `stderr` (2) | Перенаправляет только поток ошибок; обычный вывод остается в терминале. | `nginx -t 2> /tmp/syntax_errors.log` |
| `&>` | `stdout` + `stderr` | Направляет и стандартный вывод, и поток ошибок в один целевой файл. | `app_build.sh &> /tmp/build.log` |
| `2>&1` | `stderr` в `stdout` | Дублирует файловый дескриптор 2 в дескриптор 1. | `command > /tmp/out.log 2>&1` |
| `\|` | `stdout` в `stdin` | Передает стандартный вывод первой команды на вход второй команде. | `ps -eo pid,%cpu,comm \| grep nginx` |

## 2. Анализ процессов, сигналы и управление заданиями

Мониторинг дерева процессов, фильтрация списков, применение протокола эскалации сигналов и управление заданиями терминала.

| Команда | Основные флаги и синтаксис | Применение в production (когда и зачем) | Пример использования |
| :--- | :--- | :--- | :--- |
| `ps` | `aux`<br>`-ef`<br>`-eo <поля>`<br>`-p <pid>` | Снимок активных процессов. `aux` дает метрики памяти и CPU в стиле BSD; `-ef` показывает родительский PPID в стиле POSIX; `-eo` настраиваемые колонки; `-p` выбор конкретного PID. | `ps aux \| grep worker`<br>`ps -eo pid,ppid,user,%cpu,comm --sort=-%cpu`<br>`ps -p 4520` |
| `htop` | Интерактивный UI | Интерактивный монитор системных ресурсов в реальном времени. Наглядная визуализация загрузки ядер CPU, памяти, swap и дерева процессов. | `htop` |
| `pgrep` | `-fl <шаблон>`<br>`-f <шаблон>` | Поиск в таблице процессов ядра по шаблону. Флаг `-f` проверяет аргументы командной строки; `-l` выводит имя процесса вместе с PID. | `pgrep -fl "db_sync_worker"`<br>`pgrep -f "sleep 300"` |
| `kill` | `-15 <pid>`<br>`-9 <pid>`<br>`-1 <pid>` | Отправка сигналов POSIX процессу по PID. `-15` (SIGTERM) запрос корректного завершения; `-9` (SIGKILL) безусловное уничтожение ядром; `-1` (SIGHUP) перечитка конфигурации. | `kill -15 2840`<br>`kill -9 2840`<br>`kill -1 $(pgrep nginx)` |
| `sleep` | `<секунды>` | Приостановка выполнения на заданное время. Используется для ожидания в скриптах эскалации сигналов или создания фоновых таймеров. | `sleep 2`<br>`sleep 300 &` |
| `jobs` | `-l` | Список активных фоновых заданий текущей сессии оболочки. Флаг `-l` выводит связанные с ними числовые PID. | `jobs -l` |
| `fg` | `%<номер_задания>` | Перевод фонового задания на передний план терминала. | `fg %1` |
| `bg` | `%<номер_задания>` | Возобновление выполнения приостановленного процесса (`Ctrl+Z`) в фоновом режиме. | `bg %1` |
| `nohup` | `nohup <команда> &` | Запуск команды с игнорированием сигнала обрыва терминала `SIGHUP`. Предотвращает остановку процесса при разрыве SSH-сессии. | `nohup ./sync_data.sh > /tmp/sync.log 2>&1 &` |

### Сравнение стилей вызова `ps`

| Вызов команды | Формат вывода и колонки | Практическая ценность в эксплуатации |
| :--- | :--- | :--- |
| `ps aux` | `USER, PID, %CPU, %MEM, VSZ, RSS, TTY, STAT, START, TIME, COMMAND` | Анализ потребления памяти (`VSZ`/`RSS`), процессора и состояний процессов (`STAT`). |
| `ps -ef` | `UID, PID, PPID, C, STIME, TTY, TIME, CMD` | Отслеживание родительского PID (`PPID`) для поиска супервизоров и процессов-демонов. |
| `ps -eo pid,ppid,user,%cpu,comm --sort=-%cpu` | Минималистичный структурированный вывод с сортировкой по нагрузке на процессор. | Автоматизированный мониторинг и диагностика узких мест производительности. |

## 3. Управление пользователями, права доступа и делегирование в Sudo

Управление учетными записями, настройка дискреционного контроля доступа (DAC), проверка обхода каталогов и безопасное делегирование прав.

| Команда | Основные флаги и синтаксис | Применение в production (когда и зачем) | Пример использования |
| :--- | :--- | :--- | :--- |
| `groupadd` | `<группа>` | Создание новой группы безопасности для совместного доступа. | `sudo groupadd devops_team` |
| `useradd` | `-m`<br>`-s <оболочка>`<br>`-G <группы>` | Создание учетной записи. `-m` создает домашний каталог (`/home/<user>`); `-s` задает оболочку входа; `-G` дополнительные группы. | `sudo useradd -m -s /bin/bash -G devops_team dev_alex` |
| `usermod` | `-aG <группы>`<br>`-s <оболочка>` | Изменение учетной записи. Флаги `-aG` добавляют группы без сброса существующих членств (без `-a` остальные группы удаляются!). | `sudo usermod -aG devops_team dev_alex`<br>`sudo usermod -s /bin/bash dev_alex` |
| `userdel` | `-r` | Удаление учетной записи. Флаг `-r` рекурсивно удаляет домашний каталог и почтовый ящик пользователя. | `sudo userdel -r dev_alex` |
| `chmod` | `<маска>`<br>`+x`<br>`-R` | Изменение битов прав доступа DAC. Стандартные маски: `755` (каталоги/бинарники), `750` (командные папки), `644` (публичные файлы), `640` (приватные файлы), `440` (правила sudoers). | `sudo chmod 750 /opt/shared_app`<br>`sudo chmod 640 /opt/shared_app/config.env`<br>`sudo chmod 440 /etc/sudoers.d/dev_alex_nginx` |
| `chown` | `<пользователь>:<группа>`<br>`:<группа>`<br>`-R` | Изменение пользователя-владельца и группы. Конструкция `:<группа>` меняет только группу. Флаг `-R` рекурсивно обходит каталоги. | `sudo chown -R dev_alex:devops_team /opt/shared_app`<br>`sudo chown :devops_team /opt/shared_app` |
| `namei` | `-l <путь>` | Проверка прав доступа и владельцев для каждого родительского узла каталога от корня `/` до целевого файла. | `namei -l /var/www/html/index.html`<br>`namei -l /opt/shared_app/config.env` |
| `id` | `<пользователь>` | Вывод числовых UID, основного GID и списка всех дополнительных групп. Используется для валидации прав в скриптах. | `id dev_alex`<br>`id www-data` |
| `sudo` | `-u <пользователь>`<br>`-l` | Выполнение команд с повышенными привилегиями. `-u` выполняет команду от имени целевого пользователя; `-l` выводит список разрешенных команд. | `sudo -u dev_alex sudo -l`<br>`sudo -u dev_alex cat /opt/shared_app/config.env` |
| `visudo` | `-c` | Проверка синтаксиса `/etc/sudoers` и файлов в `/etc/sudoers.d/`. Флаг `-c` выполняет валидацию без открытия текстового редактора. | `sudo visudo -c` |

## 4. Сетевые сокеты, управление Systemd и диагностические утилиты

Опрос сокетов ядра, управление жизненным циклом демонов, анализ журналов systemd и диагностика сетевых уровней 4 и 7.

| Команда | Основные флаги и синтаксис | Применение в production (когда и зачем) | Пример использования |
| :--- | :--- | :--- | :--- |
| `ss` | `-t` (TCP)<br>`-u` (UDP)<br>`-n` (числовой)<br>`-l` (слушающие)<br>`-p` (процесс) | Опрос структур сетевых сокетов в ядре Linux. Комбинация `-tunlp` отображает активные слушающие порты, адреса привязки и PID процессов-владельцев. | `sudo ss -tunlp`<br>`sudo ss -tunlp \| grep :80` |
| `systemctl` | `status`<br>`start / stop`<br>`restart / reload`<br>`mask / unmask`<br>`is-active`<br>`daemon-reload`<br>`reset-failed` | Управление юнитами и жизненным циклом демонов в Systemd. `reload` перезагружает конфиг без простоя; `mask` блокирует запуск через симлинк в `/dev/null`; `unmask` снимает блокировку; `daemon-reload` обновляет кэш конфигураций; `reset-failed` сбрасывает ошибки. | `sudo systemctl status nginx`<br>`sudo systemctl reload nginx`<br>`sudo systemctl mask nginx`<br>`sudo systemctl unmask nginx`<br>`systemctl is-active nginx` |
| `journalctl` | `-u <юнит>`<br>`-xe`<br>`--no-pager` | Чтение системного журнала journald. `-u` фильтрует логи по юниту; `-x` добавляет каталожные пояснения; `-e` переходит к последним записям; `--no-pager` выводит лог напрямую в терминал. | `sudo journalctl -xeu nginx --no-pager` |
| `nginx` | `-t` | Валидация синтаксиса конфигурационных файлов веб-сервера Nginx без перезапуска рабочих процессов. | `sudo nginx -t` |
| `nc` | `-zv <хост> <порт>`<br>`-lk -p <порт>` | Утилита проверки сетевых соединений TCP/UDP. Флаги `-zv` выполняют проверку TCP 3-way handshake на транспортном уровне. `-lk -p` открывает слушающий тестовый сокет. | `nc -zv 127.0.0.1 80`<br>`sudo nc -lk -p 80 &` |
| `curl` | `-I` (HEAD)<br>`-s` (тихий)<br>`-o /dev/null`<br>`-w "<шаблон>"` | Передача данных по HTTP/HTTPS. `-I` запрашивает только заголовки ответа; комбинация `-s -o /dev/null -w "%{http_code}\n"` извлекает числовой HTTP-код для автоматизации. | `curl -I http://127.0.0.1:80`<br>`curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:80` |

### Сравнительный выбор диагностических утилит

| Задача диагностики | Оптимальная команда и флаги | Обоснование выбора |
| :--- | :--- | :--- |
| **Проверка, слушает ли порт 80** | `sudo ss -tunlp \| grep :80` | Отображает состояние сокета, локальный адрес привязки и PID процесса. |
| **Проверка доступности порта (Уровень 4)** | `nc -zv 127.0.0.1 80` | Выполняет 3-стороннее рукопожатие TCP без отправки прикладных данных. |
| **Проверка ответа веб-сервера (Уровень 7)** | `curl -I http://127.0.0.1:80` | Отправляет HTTP HEAD-запрос для проверки HTTP-статуса и заголовков сервера. |
| **Извлечение HTTP-кода в скриптах** | `curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:80` | Возвращает чистый числовой статус (`200` или `502`) для проверок в скриптах. |

### Переменные форматирования вывода `curl -w` (--write-out)

| Идентификатор переменной | Описание извлекаемой метрики | Назначение в мониторинге и SRE |
| :--- | :--- | :--- |
| `%{http_code}` | Числовой HTTP-код ответа сервера (например, `200`, `301`, `403`, `502`). | Автоматизированные проверки работоспособности, алертинг доступности и тесты в CI/CD. |
| `%{response_code}` | Протоколонезависимый числовой код ответа (синоним `http_code`). | Универсальное извлечение статуса для протоколов HTTP, FTP и других. |
| `%{http_version}` | Согласованная версия протокола HTTP (`1.1`, `2`, `3`). | Проверка корректности апгрейда протокола до HTTP/2 или HTTP/3 за балансировщиком нагрузки. |
| `%{content_type}` | Значение заголовка `Content-Type` ответа сервера (например, `text/html`). | Проверка возврата ожидаемого MIME-типа вместо HTML-страницы с ошибкой. |
| `%{remote_ip}` | IP-адрес удаленного сервера или прокси, ответившего на соединение. | Подтверждение направления трафика на нужный узел или edge-сервер CDN, исключая старые DNS-записи. |
| `%{remote_port}` | Номер удаленного порта, на который установлено подключение (`80`, `443`, `8080`). | Проверка корректности проброса портов, правил обратного прокси или маппинга в контейнерах. |
| `%{time_namelookup}` | Время (в секундах) от старта запроса до завершения DNS-разрешения имени. | Локализация задержек при медленной работе DNS-серверов или ошибках в `/etc/resolv.conf`. |
| `%{time_connect}` | Время (в секундах) от начала запроса до завершения 3-стороннего рукопожатия TCP. | Измерение задержки на сетевом транспортном уровне между клиентом и сервером. |
| `%{time_starttransfer}` | Время (в секундах) до получения первого байта ответа от сервера (TTFB). | Оценка скорости обработки запроса бэкенд-приложением. |
| `%{time_total}` | Общее время выполнения транзакции (в секундах) от старта до завершения передачи. | Контроль выполнения соглашений об уровне обслуживания (SLA) и бенчмаркинг задержек. |
