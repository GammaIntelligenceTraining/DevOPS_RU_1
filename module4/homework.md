## Задание: Анализ процессов и протокол эскалации сигналов

### Сценарий
После прерывания задачи на тестовом сервере остался работать фоновый процесс синхронизации базы данных (`db_sync_worker`). Процесс находится в бесконечном цикле и каждую секунду дописывает метки времени в файл `/tmp/db_sync.log`. Ваша цель — обнаружить процесс, определить его родительский идентификатор (PPID) и выполнить пошаговую эскалацию сигналов для корректного завершения программы без появления зомби и потерянных подоболочек.

### Порядок выполнения:

1. **Подготовка тестового окружения:**
   Выполните блок команд ниже для создания исполняемого скрипта воркера и его фонового запуска:
   ```bash
   cat << 'EOF' > /tmp/db_sync_worker
   #!/bin/bash
   while true; do
       echo "[$(date +%T)] DB_SYNC_HEARTBEAT - OK" >> /tmp/db_sync.log
       sleep 1
   done
   EOF
   chmod +x /tmp/db_sync_worker
   /tmp/db_sync_worker &
   ```

2. **Обнаружение процесса и анализ иерархии:**
   - Используйте утилиту `pgrep` с флагом вывода имени процесса (`-l`) для поиска: `pgrep -l "db_sync_worker"` (или флаг `-fl` для проверки полной строки аргументов).
   - Используйте утилиту `ps` с кастомным набором колонок (`-eo`) для определения PID, родительского идентификатора (`PPID`), пользователя-владельца, процента загрузки CPU и имени команды.
   - Зафиксируйте числовой PID процесса.

3. **Проверка активности процесса:**
   - Выведите последние 5 строк файла `/tmp/db_sync.log`, чтобы убедиться, что воркер непрерывно записывает данные на диск:
   ```bash
   # Просмотр последних 5 записей файла журнала (tail: -n 5 — вывод последних 5 строк)
   tail -n 5 /tmp/db_sync.log
   ```

4. **Выполнение протокола эскалации сигналов:**
   - **Шаг 4A (Запрос корректной остановки):** Отправьте сигнал `SIGTERM` (сигнал 15) обнаруженному процессу. Выдержите паузу в 3 секунды, чтобы процесс мог корректно закрыть файловые дескрипторы.
   - **Шаг 4B (Проверка таблицы процессов):** Проверьте состояние процесса с помощью `ps -p <PID>`.
   - **Шаг 4C (Принудительное уничтожение при необходимости):** Если процесс не завершился, отправьте сигнал `SIGKILL` (сигнал 9) для принудительного освобождения памяти ядром.
   - **Шаг 4D (Финальная верификация):** Убедитесь, что PID полностью удален из таблицы процессов (`ps -p <PID>` возвращает ошибку или пустой результат), и проверьте, что запись в `/tmp/db_sync.log` прекратилась.

### Технический справочник по командам

| Команда / Флаг | Техническая функция | Диагностическое назначение |
| :--- | :--- | :--- |
| `pgrep -fl <имя>` | Поиск в таблице процессов по имени и аргументам. | Быстрое определение PID целевого процесса без конвейеров grep. |
| `ps -eo pid,ppid,user,%cpu,comm` | Отображение настраиваемых колонок таблицы процессов. | Определение родительского процесса (PPID) и нагрузки на CPU. |
| `kill -15 <PID>` | Отправка сигнала `SIGTERM` (сигнал 15). | Запрос на корректное завершение с сохранением данных и закрытием файлов. |
| `kill -9 <PID>` | Отправка сигнала `SIGKILL` (сигнал 9). | Безусловная остановка ядром при зависании процесса. |
| `ps -p <PID>` | Проверка наличия конкретного PID в ядре. | Ненулевой код возврата подтверждает полное завершение процесса. |

### Что необходимо предоставить:
- Лог терминала, содержащий:
  1. Команду поиска запущенного процесса `db_sync_worker` и его родительского PID.
  2. Отправку сигнала `kill -15` и последующую проверку состояния процесса.
  3. Отправку сигнала `kill -9` (если потребовалась) и подтверждение удаления процесса.
  4. Вывод команды `tail -n 3 /tmp/db_sync.log`, подтверждающий остановку записи новых строк.
