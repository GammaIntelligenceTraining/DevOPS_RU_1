## Задание: Оркестратор развертывания инфраструктуры (`cluster_provisioner.sh`)

### Сценарий
В инфраструктурной команде требуется автоматизировать пакетный ввод серверов в эксплуатацию. Список целевых узлов, их IP-адресов и назначенных ролей хранится в текстовом файле инвентаря `inventory.txt`. Скрипт-оркестратор должен проверить целостность файла, последовательно обработать каждый сервер, проверить доступность целевого сервисного порта в соответствии с ролью узла, распределить результаты по спискам и сформировать аналитический отчет с процентом успешности.

### Технические требования

1. **Интерпретатор и защитный режим:**
   - Скрипт должен начинаться со стандартного шебанга `#!/bin/bash`.
   - В начале скрипта должен быть активирован строгий режим защиты: `set -euo pipefail`.
2. **Конфигурационный словарь ролей:**
   - Создайте ассоциативный массив с обязательным предварительным объявлением `declare -A ROLE_PORTS`.
   - Заполните словарь следующими соответствиями:
     - `web` — порт `80`
     - `api` — порт `8080`
     - `db` — порт `5432`
     - `cache` — порт `6379`
3. **Модульная функция валидации аргументов (`validate_environment`):**
   - Функция должна принимать один аргумент — путь к файлу инвентаря.
   - С помощью каскадной проверки `if / elif / else` и операторов `&&`, `!`:
     - Если аргумент не передан (`-z "$1"`), выведите в поток ошибок `stderr` руководство: `Использование: $0 <путь_к_файлу_инвентаря>` и верните статус ошибки `return 1`.
     - Если файл не существует (`! -f "$1"`), выведите в `stderr` сообщение: `Ошибка: файл $1 не найден` и верните статус `return 2`.
     - Если файл существует, но недоступен для чтения текущему пользователю (`! -r "$1"`), выведите в `stderr` сообщение: `Ошибка: нет прав на чтение файла $1` и верните статус `return 3`.
     - При успешной проверке верните `return 0`.
4. **Модульная функция аудита сетевого порта узла (`check_port`):**
   - Функция принимает два параметра: `local host="$1"` и `local port="$2"`.
   - Выполняет опрос порта с коротким таймаутом соединения не более 2 секунд:
     `/usr/bin/curl --connect-timeout 2 -s -o /dev/null "http://${host}:${port}"`
   - С помощью `if [[ $? -eq 0 ]]` проверяет успешность соединения:
     - При успешном соединении возвращает `return 0`.
     - При сбое подключения возвращает `return 1`.
5. **Построчная обработка инвентаря (`while read -r`):**
   - Инициализируйте два индексированных массива: `declare -a SUCCESS_HOSTS=()` и `declare -a FAILED_HOSTS=()`.
   - Организуйте чтение файла инвентаря строка за строкой с помощью цикла `while read -r HOSTNAME IP ROLE || [[ -n "$HOSTNAME" ]]; do ... done < "$INVENTORY_FILE"`.
   - Внутри цикла предусмотрите защиту от пустых строк и комментариев:
     - Если строка начинается с символа `#` или переменная `$HOSTNAME` пуста, выполните `continue`.
   - С помощью условного оператора проверьте, существует ли роль в ассоциативном массиве (`[[ -n "${ROLE_PORTS[$ROLE]:-}" ]]`):
     - Если роль неизвестна, выведите предупреждение: `Неизвестная роль '$ROLE' для хоста $HOSTNAME` и добавьте хост в массив `FAILED_HOSTS+=("$HOSTNAME")`.
     - Если роль известна, получите назначенный порт из словаря и вызовите функцию `check_port "$IP" "$PORT"`.
     - Если функция вернула 0, выведите статус `[OK] $HOSTNAME ($ROLE:$PORT) доступен` и добавьте запись в `SUCCESS_HOSTS+=("$HOSTNAME")`.
     - Если функция вернула ненулевой код, выведите статус `[FAIL] $HOSTNAME ($ROLE:$PORT) не отвечает` и добавьте запись в `FAILED_HOSTS+=("$HOSTNAME")`.
6. **Расчет метрик и вывод отчета:**
   - Определите общее число обработанных узлов:
     `TOTAL_NODES=$(( ${#SUCCESS_HOSTS[@]} + ${#FAILED_HOSTS[@]} ))`.
   - Если `TOTAL_NODES` больше нуля, вычислите процент успешно развернутых узлов:
     `SUCCESS_PERCENT=$(( (${#SUCCESS_HOSTS[@]} * 100) / TOTAL_NODES ))`.
   - Выведите сводную информацию:
     - Общее число проверенных узлов.
     - Количество успешных узлов и их список через `"${SUCCESS_HOSTS[@]}"`.
     - Количество сбойных узлов и их список через `"${FAILED_HOSTS[@]}"`.
     - Итоговый процент успешности (`$SUCCESS_PERCENT%`).
7. **Код возврата скрипта:**
   - Если массив `FAILED_HOSTS` содержит хотя бы один элемент (`${#FAILED_HOSTS[@]} -gt 0`), завершите скрипт с кодом `1`.
   - Если все узлы отработали успешно, завершите работу с кодом `0`.

## Синтаксические примеры и подсказки

Для объявления функции с изолированными локальными переменными и явным кодом возврата используйте следующий шаблон:
```bash
check_status() {
    local target_name="$1"
    local exit_code=0
    
    # Проверка: передан ли обязательный параметр имени цели
    if [[ -z "$target_name" ]]; then
        return 1
    fi
    
    return "$exit_code"
}
```

Для проверки существования ключа в ассоциативном массиве используется проверка длины строки с защитой от отсутствующего значения:
```bash
declare -A PORT_MAP
PORT_MAP["http"]=80

ROLE="http"
# Проверка: зарегистрирована ли роль в ассоциативном массиве портов
if [[ -n "${PORT_MAP[$ROLE]:-}" ]]; then
    echo "Порт найден: ${PORT_MAP[$ROLE]}"
else
    echo "Роль не зарегистрирована в конфигурации"
fi
```

Для безопасного построчного чтения структурированного файла с разделением колонок по пробелам используется чтение нескольких переменных в цикле:
```bash
# Построчное чтение файла с защитой от отсутствия завершающего перевода строки
while read -r COL1 COL2 COL3 || [[ -n "$COL1" ]]; do
    # Проверка: пропуск пустых строк и строк-комментариев
    if [[ -z "$COL1" || "$COL1" == "#"* ]]; then
        continue
    fi
    echo "Обработка записи: $COL1, адрес: $COL2, роль: $COL3"
done < /path/to/data.txt
```

Для добавления элементов в индексированный массив и вычисления его длины используются круглые скобки и префикс `#`:
```bash
declare -a PROCESSED=()
PROCESSED+=("node-01")
PROCESSED+=("node-02")

echo "Всего элементов: ${#PROCESSED[@]}"
echo "Все элементы: ${PROCESSED[@]}"
```

## Порядок проверки решения

Подготовьте тестовый инвентарный файл `inventory.txt` со следующими строками:
```bash
cat << 'EOF' > /tmp/inventory.txt
# Список серверов для ввода в эксплуатацию
app-web 127.0.0.1 web
app-api 127.0.0.1 api

# Сервер с неактивным портом
app-cache 127.0.0.1 cache
# Сервер с неизвестной ролью
unknown-srv 127.0.0.1 custom_role
EOF
```

Убедитесь, что веб-сервер Nginx запущен и слушает порт 80:
```bash
sudo /usr/bin/systemctl start nginx
```

Сделайте скрипт исполняемым и проверьте валидацию аргументов:
```bash
chmod +x cluster_provisioner.sh
./cluster_provisioner.sh
```

Проверьте реакцию на несуществующий файл инвентаря:
```bash
./cluster_provisioner.sh /path/to/missing_inventory.txt
```

Запустите скрипт с подготовленным инвентарем:
```bash
./cluster_provisioner.sh /tmp/inventory.txt
```

Проверьте код возврата скрипта (ожидается код 1 из-за наличия сбойных портов и неизвестной роли):
```bash
echo $?
```

В выводе терминала должны отображаться статусы по каждому узлу, разделение на списки успешных и сбойных серверов, а также точный процент успешности.
