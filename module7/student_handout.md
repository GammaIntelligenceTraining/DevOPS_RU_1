# Модуль 7: Продвинутая автоматизация на Bash и структуры данных

Практическое инженерное руководство по продвинутым конструкциям командного интерпретатора Bash: разветвленные условия `if / elif / else`, модульные функции, структуры данных (индексированные и ассоциативные массивы), целочисленная арифметика, потоковое чтение в циклах `while` и защитные флаги отказоустойчивости.

---

## 1. Углубленные условные конструкции и ветвление

В базовых сценариях автоматизации достаточно простых условий вида `if ... else`. Однако в реальных инфраструктурных скриптах требуется обрабатывать множественные взаимно исключающие состояния сервисов и комбинировать логические проверки.

### 1.1 Разветвление через `if / elif / else`

Конструкция `elif` (сокращение от else if) позволяет выстраивать цепочки проверок, которые вычисляются строго сверху вниз до первого истинного условия. Как только одно из условий оказывается истинным, соответствующий блок команд выполняется, а все последующие ветки `elif` и `else` пропускаются.

Для демонстрации каскадной проверки статуса сетевого порта и прав доступа используется цепочка `if / elif / else`:

```bash
TARGET_PORT=80
IS_PRIVILEGED=0

# Проверка: требует ли порт привилегий root при запуске без sudo
if [[ "$TARGET_PORT" -lt 1024 && "$IS_PRIVILEGED" -eq 0 ]]; then
    echo "Ошибка: порты ниже 1024 требуют прав суперпользователя."
# Проверка: находится ли порт в пользовательском диапазоне
elif [[ "$TARGET_PORT" -ge 1024 && "$TARGET_PORT" -le 65535 ]]; then
    echo "Порт $TARGET_PORT относится к пользовательскому диапазону."
else
    echo "Порт $TARGET_PORT разрешен для непривилегированного запуска."
fi
```

### 1.2 Составные условия в двойных скобках `[[ ... ]]`

Современный Bash использует расширенную конструкцию `[[ ... ]]`, которая обеспечивает безопасную обработку переменных с пробелами и поддерживает встроенные логические операторы:
- `&&` — логическое И (условие истинно только тогда, когда истинны обе части проверки).
- `||` — логическое ИЛИ (условие истинно, если истинна хотя бы одна из частей).
- `!` — логическое отрицание (инвертирует результат проверки).

Следующий пример проверяет наличие файла конфигурации и права на его чтение перед открытием, предотвращая аварийное завершение скрипта:

```bash
CONFIG_PATH="/etc/nginx/nginx.conf"

# Проверка: существует ли файл и доступен ли он текущему пользователю на чтение
if [[ -f "$CONFIG_PATH" && -r "$CONFIG_PATH" ]]; then
    echo "Конфигурационный файл найден и доступен для чтения."
# Проверка: существует ли файл без необходимых прав на чтение
elif [[ -f "$CONFIG_PATH" && ! -r "$CONFIG_PATH" ]]; then
    echo "Файл существует, но у текущего пользователя нет прав на чтение."
else
    echo "Конфигурационный файл отсутствует в системе."
fi
```

### 1.3 Проверка статуса выполнения команд в `if`

Каждая команда Linux при завершении возвращает числовой код (Exit Code) от `0` до `255`. Код `0` всегда означает успешное выполнение, а ненулевой код сигнализирует об ошибке. Конструкция `if` умеет напрямую оценивать код возврата любой утилиты без явного вызова скобок `[[ ]]`.

Следующий пример выполняет проверку доступности внешнего шлюза, подавляя стандартный вывод утилиты и передавая в условие только результат ее завершения:

```bash
# Проверка: успешно ли завершился сетевой опрос утилитой ping (код возврата 0)
if /usr/bin/ping -c 1 -W 2 127.0.0.1 > /dev/null 2>&1; then
    echo "Сетевой стек активен, петлевой интерфейс отвечает."
else
    echo "Сетевой интерфейс недоступен."
fi
```

## 2. Модульные функции в Bash и область видимости

По мере роста сценариев автоматизации монолитный код становится трудным для чтения, тестирования и повторного использования. Функции в Bash позволяют объединять повторяющиеся операции в изолированные блоки логики.

### 2.1 Объявление и позиционные параметры функций

Функция определяется с помощью имени и круглых скобок `function_name() { ... }`. Внутри тела функции аргументы доступны через стандартные позиционные переменные `$1`, `$2`, а общее число аргументов функции хранится в `$#`.

Следующий пример объявляет функцию логирования, которая принимает уровень важности и текст сообщения, форматируя вывод с отметкой времени:

```bash
log_event() {
    local level="$1"
    local message="$2"
    local timestamp
    timestamp="$(/usr/bin/date '+%Y-%m-%d %H:%M:%S')"
    echo "[$timestamp] [$level] $message"
}

log_event "INFO" "Инициализация службы мониторинга."
log_event "WARN" "Превышен порог использования памяти: 82%."
```

### 2.2 Локальные переменные (`local`) и возврат статуса (`return`)

По умолчанию все переменные в Bash являются глобальными, даже если они созданы внутри функции. Если случайно изменить переменную с именем, уже используемым в основном теле скрипта, это приведет к скрытым ошибкам (побочным эффектам). Чтобы изолировать переменную внутри функции, обязательно используется ключевое слово `local`.

Для передачи результата из функции используются две различные механики:
1. **Код возврата (`return N`):** возвращает целочисленный код завершения (от 0 до 255), который проверяется через переменную `$?` или сразу внутри `if`.
2. **Возврат данных (`stdout`):** функция выводит текстовый результат через команду `echo`, а вызывающий код захватывает его с помощью подстановки `RESULT="$(my_func)"`.

Следующий пример демонстрирует функцию проверки прав администратора, возвращающую код завершения с помощью директивы `return`:

```bash
check_root_privileges() {
    # Проверка: запущен ли скрипт от имени суперпользователя root (EUID=0)
    if [[ "$EUID" -eq 0 ]]; then
        return 0
    else
        return 1
    fi
}

# Проверка: завершилась ли функция валидации с успешным кодом 0
if check_root_privileges; then
    echo "Скрипт запущен с правами администратора root."
else
    echo "Ошибка: требуются повышенные привилегии." >&2
fi
```

## 3. Типы данных и арифметика в Bash

В отличие от языков программирования общего назначения (Go, Python), в Bash все переменные по умолчанию хранятся как строки ASCII. Однако командная оболочка предоставляет встроенные механизмы для арифметических вычислений и работы со сложными коллекциями.

### 3.1 Целочисленная арифметика `$(( ))`

Для выполнения математических операций выражение необходимо помещать внутри конструкции `$(( ... ))`. 

> [!IMPORTANT]
> Bash поддерживает только **целочисленные операции**. Любые дробные части чисел отсекаются (округление вниз к нулю). Например, `$(( 10 / 3 ))` вернет `3`, а не `3.33`.

Поддерживаемые арифметические операторы:
- `+` сложение, `-` вычитание.
- `*` умножение.
- `/` целочисленное деление.
- `%` вычисление остатка от деления (модуль).

Следующий пример рассчитывает утилизацию оперативной памяти в процентах и определяет свободный остаток:

```bash
TOTAL_MB=16384
USED_MB=4096

FREE_MB=$((TOTAL_MB - USED_MB))
PERCENT_USED=$(( (USED_MB * 100) / TOTAL_MB ))

echo "Свободно памяти: $FREE_MB MB"
echo "Процент использования: $PERCENT_USED%"
```

### 3.2 Управление атрибутами переменных с помощью `declare`

Встроенная команда `declare` позволяет строго зафиксировать тип или поведение переменной:
- `declare -i` — целочисленная переменная (значения автоматически вычисляются математически).
- `declare -r` — переменная только для чтения (константа, которую нельзя изменить или удалить).
- `declare -l` — автоматическое преобразование значения в нижний регистр.
- `declare -u` — автоматическое преобразование значения в верхний регистр.
- `declare -a` — индексированный массив (список).
- `declare -A` — ассоциативный массив (словарь / хеш-таблица).

Следующий пример демонстрирует использование констант и приведение строк к нижнему регистру:

```bash
declare -r DEFAULT_CONFIG="/etc/app.conf"
declare -l SERVICE_ENV="PRODUCTION"

echo "Конфигурация: $DEFAULT_CONFIG"
echo "Нормализованное окружение: $SERVICE_ENV"
```

### 3.3 Индексированные массивы (Списки)

Индексированный массив хранит упорядоченную последовательность элементов с доступом по числовому индексу, начиная с `0`.

Синтаксические конструкции работы с массивами:
- `declare -a LIST=("val1" "val2")` — создание и инициализация списка.
- `LIST+=("val3")` — добавление элемента в конец списка (круглые скобки обязательны).
- `${LIST[0]}` — получение первого элемента.
- `"${LIST[@]}"` — обращение ко всем элементам списка (кавычки предотвращают разбиение элементов с пробелами).
- `${#LIST[@]}` — подсчет общего количества элементов в массиве.

Следующий скрипт инициализирует массив серверов кластера, добавляет новый узел и выводит общее число управляемых машин:

```bash
# Флаг -a (array) указывает Bash явно инициализировать переменную как индексированный массив (список с индексами от 0)
declare -a CLUSTER_NODES=("node-01" "node-02" "node-03")
CLUSTER_NODES+=("node-04")

echo "Первый узел: ${CLUSTER_NODES[0]}"
echo "Всего узлов в кластере: ${#CLUSTER_NODES[@]}"

for NODE in "${CLUSTER_NODES[@]}"; do
    echo "Синхронизация конфигурации на узле: $NODE"
done
```

### 3.4 Ассоциативные массивы (Словари / Хеш-таблицы)

Ассоциативный массив хранит пары "ключ — значение", где в роли ключа выступает произвольная строка (например, имя хоста или название сервиса).

> [!WARNING]
> Ассоциативные массивы **обязательно** должны объявляться через `declare -A` перед первым использованием. Без явного объявления интерпретатор попытается трактовать строковый ключ как числовое выражение, что приведет к синтаксической ошибке.

Синтаксические правила для ассоциативных массивов:
- `declare -A MAP` — обязательное объявление ассоциативного массива (флаг `-A` задает структуру хеш-таблицы со строковыми ключами, в отличие от `-a` для числовых списков).
- `declare -A MAP=(["k1"]="v1" ["k2"]="v2")` — компактное литеральное создание и заполнение ассоциативного массива в одну строку.
- `MAP["key"]="value"` — сохранение значения по ключу.
- `${MAP["key"]}` — чтение значения по ключу.
- `"${!MAP[@]}"` — извлечение всех ключей массива (префикс `!`).
- `"${MAP[@]}"` — извлечение всех сохраненных значений.
- `unset MAP["key"]` — удаление элемента из массива по ключу.

Следующий пример демонстрирует два способа создания ассоциативных массивов — поэлементное наполнение и компактную литеральную инициализацию микросервисов:

```bash
# Способ 1: Отдельное объявление и поэлементное добавление
# Флаг -A (заглавная A) указывает интерпретатору создать ассоциативный массив (словарь со строковыми ключами)
declare -A SERVICE_PORTS
SERVICE_PORTS["http"]=80
SERVICE_PORTS["https"]=443
SERVICE_PORTS["ssh"]=22

echo "Порт для HTTPS: ${SERVICE_PORTS["https"]}"

# Способ 2: Компактное литеральное объявление и инициализация словаря в одну строку
# Флаг -A задает ассоциативный массив, а синтаксис (["ключ"]="значение") заполняет его парами
declare -A SERVICE=(["auth"]="10.0.1.15:8080" ["api"]="10.0.1.20:80" ["db"]="10.0.1.30:5432")

echo "Адрес и порт микросервиса auth: ${SERVICE["auth"]}"

for SERVICE in "${!SERVICE_PORTS[@]}"; do
    echo "Сервис $SERVICE ожидает соединений на порту ${SERVICE_PORTS[$SERVICE]}"
done
```

## 4. Потоковая обработка данных и циклы `while`

Цикл `for` отлично подходит для работы с заранее известными списками и коллекциями. Однако для обработки потоков данных неизвестной длины (файлы конфигураций, дампы учетных записей, журналы системы) стандартом является цикл `while`.

### 4.1 Построчное чтение файлов (`while read -r`)

Конструкция `while read -r LINE` читает входной поток строка за строкой до тех пор, пока не будет достигнут конец файла. Флаг `-r` отключает экранирование обратных слэшей, гарантируя точную передачу исходного текста. Входной файл подается в цикл с помощью оператора перенаправления `<` в конце блока `done`.

Следующий пример создает файл списка сетевых шлюзов и последовательно обрабатывает каждую непустую строку:

```bash
echo -e "192.168.1.1\n10.0.0.1\n\n172.16.0.1" > /tmp/gateways.txt

# Построчное чтение файла с подавлением интерпретации обратных слэшей
while read -r GATEWAY_IP; do
    # Проверка: пропуск пустых строк в потоке данных
    if [[ -z "$GATEWAY_IP" ]]; then
        continue
    fi
    echo "Проверка доступности шлюза: $GATEWAY_IP"
done < /tmp/gateways.txt

rm -f /tmp/gateways.txt
```

### 4.2 Подстановка процессов `< <(...)` и ловушка Subshell

Если передать вывод команды в цикл через классический конвейер (`command | while read -r LINE`), командная оболочка выполнит весь цикл внутри отдельного дочернего процесса (Subshell). Любые переменные, счетчики и массивы, измененные внутри такого цикла, будут уничтожены в момент завершения дочернего процесса.

Для сохранения изменений в родительском скрипте используется механизм **подстановки процессов**: `while read -r LINE; do ... done < <(command)`. При таком синтаксисе цикл выполняется в текущей оболочке, а команда работает как именованный поток данных.

Следующий пример подсчитывает количество активных служб без потери значения счетчика:

```bash
ACTIVE_COUNT=0

# Построчное чтение вывода команды через подстановку процессов без создания subshell
while read -r SERVICE_NAME; do
    ACTIVE_COUNT=$((ACTIVE_COUNT + 1))
done < <(/usr/bin/systemctl list-units --type=service --state=running --no-legend | /usr/bin/awk '{print $1}')

echo "Всего активных служб в системе: $ACTIVE_COUNT"
```

### 4.3 Счетные циклы в стиле Си

Когда требуется выполнить команду фиксированное число раз без генерации временных списков, используется трехаргументный синтаксис `for (( init; condition; step ))`.

Следующий скрипт выполняет три последовательные попытки проверки статуса с интервалом:

```bash
for (( attempt=1; attempt<=3; attempt++ )); do
    echo "Попытка подключения номер $attempt..."
done
```

## 5. Промышленная надежность: тонкости поведения set -e

Изученный в Модуле 6 строгий режим `set -euo pipefail` является базовым стандартом любого скрипта автоматизации. В данном модуле мы углубляем понимание надежности: рассматриваем тонкости взаимодействия `set -e` с функциями, условиями и конвейерами.

### 5.1 Тонкости поведения `set -e` в функциях и составных конструкциях

Флаг `set -e` (`errexit`) обеспечивает немедленную остановку скрипта при сбое, однако имеет важные архитектурные особенности поведения в управляющих конструкциях:

1. **Отключение внутри условий:** Если команда или функция завершается с ненулевым кодом внутри условия `if`, проверки цикла `while` или слева от оператора `||`, интерпретатор отключает прерывание по `set -e`. В этих блоках ненулевой код завершения трактуется как штатное логическое условие «ложь».
2. **Вызов функций и return:** Если пользовательская функция возвращает ненулевой код (`return 1`) и вызывается как самостоятельная команда (вне `if`), флаг `set -e` немедленно завершает весь скрипт.
3. **Идиома нефатальных сбоев (`|| true`):** Если утилита может завершиться с ошибкой, которая не является критической (например, удаление несуществующего старого файла), команду защищают от прерывания скрипта конструкцией `команда || true`.
4. **Массив кодов конвейера `${PIPESTATUS[@]}`:** Специальный системный массив Bash хранит коды возврата каждого звена последней цепочки команд, разделенных пайпом `|`.

Следующий пример демонстрирует проверку кодов возврата звеньев конвейера и подавление прерывания для некритичных команд:

```bash
# Идиома безопасного выполнения некритичной команды при активном set -e
/usr/bin/rm -f /tmp/non_existent_file.tmp || true

# Проверка массива кодов возврата конвейера PIPESTATUS
/usr/bin/echo "Тест конвейера" | /usr/bin/grep "Тест" > /dev/null
echo "Коды завершения этапов конвейера: ${PIPESTATUS[*]}"
```

## 6. Нативная трансформация строк: Parameter Expansions в Bash

В производственных скриптах автоматизации системным администраторам регулярно требуется модифицировать строковые значения: выделять имена файлов из путей, убирать суффиксы расширений, подставлять значения по умолчанию или заменять разделители. Использование внешних утилит (`basename`, `dirname`, `cut`, `sed`) через подстановку `$(...)` порождает отдельные дочерние процессы ядра, что существенно замедляет выполнение скриптов при обработке больших списков.

Встроенный механизм Parameter Expansion выполняет строковые преобразования непосредственно в памяти процесса Bash без создания дочерних subshell.

### 6.1 Базовый DevOps-квартет трансформации параметров

1. **Значения по умолчанию (`${VAR:-default}`):** Если переменная пуста или не инициализирована, интерпретатор использует указанное резервное значение без изменения самой переменной.
2. **Обязательные переменные (`${VAR:?сообщение}`):** Если переменная не задана или пуста, интерпретатор выводит сообщение об ошибке в поток stderr и завершает скрипт с ненулевым кодом.
3. **Удаление префиксов по шаблону (`${VAR#шаблон}` и `${VAR##шаблон}`):** Символ `#` удаляет кратчайшее совпадение с начала строки, а двойной символ `##` выполняет жадное удаление максимального совпадения. Конструкция `${PATH##*/}` возвращает имя файла аналогично системной утилите `basename`.
4. **Удаление суффиксов по шаблону (`${VAR%шаблон}` и `${VAR%%шаблон}`):** Символ `%` удаляет кратчайшее совпадение с конца строки, а `%%` — максимальное совпадение. Конструкция `${FILE%.*}` удаляет последнее расширение, а `${FILE%%.*}` отсекает все расширения составных архивов.
5. **Поиск и замена подстрок (`${VAR//шаблон/замена}`):** Заменяет все вхождения указанного шаблона в строке без вызова внешнего строкового редактора `sed`.
6. **Срезы подстрок (`${VAR:смещение:длина}`):** Извлекает срез строки фиксированной длины начиная с указанной позиции индекса.

Следующий исполняемый пример демонстрирует работу с путями резервных копий и нормализацию переменных окружения:

```bash
# Значение по умолчанию: если PORT не передан, используется 8080
TARGET_PORT="${1:-8080}"
echo "Целевой сетевой порт: $TARGET_PORT"

# Полный путь к архиву базы данных
ARCHIVE_PATH="/var/backups/postgresql/2026-11-13_cluster_backup.tar.gz"

# Извлечение имени файла без запуска утилиты basename
FILE_NAME="${ARCHIVE_PATH##*/}"
echo "Имя архива: $FILE_NAME"

# Извлечение каталога без запуска утилиты dirname
DIR_PATH="${ARCHIVE_PATH%/*}"
echo "Путь к каталогу: $DIR_PATH"

# Отсечение последнего расширения .gz
NO_GZ="${FILE_NAME%.gz}"
echo "Без суффикса gz: $NO_GZ"

# Полное отсечение всех составных расширений tar.gz
BASE_NAME="${FILE_NAME%%.*}"
echo "Базовое имя файла: $BASE_NAME"

# Извлечение даты из первых 10 символов базового имени (YYYY-MM-DD)
BACKUP_DATE="${BASE_NAME:0:10}"
echo "Дата создания архива: $BACKUP_DATE"

# Замена символов дефиса на нижнее подчеркивание без вызова sed
NORMALIZED_NAME="${BASE_NAME//-/_}"
echo "Нормализованное имя: $NORMALIZED_NAME"
```
