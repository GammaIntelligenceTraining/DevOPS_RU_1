# Модуль 5: Диагностика, защита и логи — Шпаргалка по командам

Краткий справочник по командам управления фаерволом UFW, расследованию инцидентов через журналы systemd и анализу сетевых пакетов утилитой tcpdump.

---

## 1. UFW (Uncomplicated Firewall)

| Команда | Категория | Описание | Применение в продакшене и DevOps |
| :--- | :--- | :--- | :--- |
| `sudo ufw status` | Статус | Отображает рабочий статус фаервола и список активных правил | Базовый аудит статуса: проверка, активна ли фильтрация пакетов ядром в данный момент (`sudo ufw status`) |
| `sudo ufw status verbose` | Статус | Показывает подробный статус, политики по умолчанию и уровень логирования | Аудит соответствия политикам: проверка политик входящего/исходящего трафика и уровня детализации логов (`sudo ufw status verbose`) |
| `sudo ufw status numbered` | Статус | Выводит активные правила с их порядковыми номерами в квадратных скобках | Управление цепочкой правил: просмотр точных номеров индексов перед изменением или удалением записей (`sudo ufw status numbered`) |
| `sudo ufw enable` | Жизненный цикл | Активирует фаервол и включает автозапуск правил при перезагрузке системы | Ввод в эксплуатацию: запуск фильтрации сетевых пакетов и регистрация юнита systemd (`sudo ufw enable`) |
| `sudo ufw disable` | Жизненный цикл | Отключает фаервол без удаления настроенных правил | Аварийный обход: временная приостановка фильтрации для изоляции сетевых проблем маршрутизации (`sudo ufw disable`) |
| `sudo ufw reset` | Жизненный цикл | Отключает фаервол и сбрасывает все правила к заводским настройкам | Вывод хоста из эксплуатации: полная очистка наборов правил перед повторной инициализацией сервера (`sudo ufw reset`) |
| `sudo ufw default <policy> <dir>` | Политики | Задает базовую политику (`deny`, `allow`, `reject`) для входящего или исходящего трафика | Базовый профиль Zero-Trust: установка политики сброса по умолчанию для всего входящего трафика (`sudo ufw default deny incoming`) |
| `sudo ufw allow <port>/<protocol>` | Правила | Открывает указанный порт для протокола TCP или UDP | Входящий веб-трафик: открытие портов HTTP и HTTPS на стандартных продакшен-серверах (`sudo ufw allow 80/tcp`) |
| `sudo ufw allow <service>` | Правила | Открывает порт по имени службы из базы данных `/etc/services` | Авторизация службы: открытие портов управления по общепринятым именам протоколов (`sudo ufw allow ssh`) |
| `sudo ufw allow from <ip>` | Гранулярные | Разрешает весь входящий трафик с конкретного IP-адреса источника | Доступ с бастиона: разрешение неограниченного администрирования со специального хоста доступа (`sudo ufw allow from 10.0.1.25`) |
| `sudo ufw allow from <cidr> to any port <port>` | Гранулярные | Ограничивает доступ к порту указанной доверенной подсетью | Сегментация баз данных: доступ к PostgreSQL исключительно из внутренней подсети приложений (`sudo ufw allow from 10.0.4.0/24 to any port 5432 proto tcp`) |
| `sudo ufw limit <service>/<proto>` | Безопасность | Ограничивает частоту подключений (блокирует IP при >=6 попытках за 30 секунд) | Защита от перебора паролей: троттлинг атак перебора на открытых портах авторизации (`sudo ufw limit ssh/tcp`) |
| `sudo ufw deny <port>/<proto>` | Правила | Молча отбрасывает входящий трафик на порт (скрытый сброс DROP) | Маскировка портов: бесследный сброс сетевых сканеров на портах БД без отправки ответа атакующему (`sudo ufw deny 3306/tcp`) |
| `sudo ufw reject <port>/<proto>` | Правила | Сбрасывает трафик с немедленной отправкой ответа TCP RST или ICMP unreachable | Быстрый отказ в локальной сети: мгновенный сброс соединений к устаревшим сервисам для немедленного переключения клиентов (`sudo ufw reject 8080/tcp`) |
| `sudo ufw insert 1 deny from <ip>` | Безопасность | Вставляет правило блокировки с наивысшим приоритетом в начало цепочки | Реагирование на инциденты: немедленная блокировка атакующего IP на позиции 1 до обработки разрешающих правил (`sudo ufw insert 1 deny from 198.51.100.25 to any`) |
| `sudo ufw delete <number>` | Управление | Удаляет правило по его порядковому номеру из `status numbered` | Актуализация политик: удаление устаревших правил фаервола по их индексу (`sudo ufw delete 2`) |
| `sudo ufw logging <level>` | Логирование | Настраивает уровень детализации журнала (`low`, `medium`, `high`, `full`, `off`) | Настройка аудита: повышение уровня логов до medium во время расследования инцидентов для сбора метаданных пакетов (`sudo ufw logging medium`) |

## 2. Расследование журналов Systemd (`journalctl`)

| Команда | Область | Описание | Применение в продакшене и DevOps |
| :--- | :--- | :--- | :--- |
| `sudo journalctl -k` | Ядро | Запрашивает сообщения кольцевого буфера ядра | Аудит фаервола: просмотр записей ядра Netfilter о заблокированных пакетах (`[UFW BLOCK]`) (`sudo journalctl -k`) |
| `sudo journalctl -kf` | Ядро | Непрерывно транслирует новые события ядра в реальном времени | Мониторинг периметра: онлайн-просмотр блокировок пакетов при атаках сканирования портов (`sudo journalctl -kf`) |
| `sudo journalctl -u <unit>` | Сервис | Отображает строки лога конкретного системного юнита systemd | Аудит сервиса: анализ жизненного цикла процесса и стандартных потоков демона (`sudo journalctl -u nginx.service`) |
| `sudo journalctl -u <unit1> -u <unit2>` | Корреляция | Объединяет потоки логов нескольких юнитов в хронологическом порядке | Межуровневая отладка: сопоставление событий веб-прокси и внутреннего сервиса в едином таймлайне (`sudo journalctl -u ssh.service -u nginx.service`) |
| `sudo journalctl -u <unit> -f` | Сервис | Потоковый просмотр новых записей журнала выбранного сервиса | Проверка деплоя: наблюдение за запуском приложения и входящими запросами во время релиза (`sudo journalctl -u nginx.service -f`) |
| `sudo journalctl -xeu <unit>` | Диагностика | Выводит логи с расширенными пояснениями системного каталога | Диагностика сбоев: быстрый переход к последним ошибкам сервиса с пояснениями причин падения (`sudo journalctl -xeu nginx.service`) |
| `sudo journalctl -p <priority> -b` | Важность | Фильтрует сообщения по уровню критичности (0-7) за текущую загрузку | Поиск ошибок: выборка системных событий для отображения только сбоев и критических предупреждений (`sudo journalctl -p err -b`) |
| `sudo journalctl --since "<window>"` | Временное окно | Отображает записи журнала за указанный относительный промежуток времени | Локализация инцидента: анализ телеметрии системы за конкретный интервал аварии (`sudo journalctl --since "15m ago"`) |
| `journalctl --list-boots` | Аудит загрузок | Выводит список всех зарегистрированных циклов загрузки хоста | Анализ перезагрузок: определение истории перезапусков хоста и уникальных идентификаторов загрузок (`journalctl --list-boots`) |
| `sudo journalctl -b -1` | Аудит загрузок | Отображает сообщения сессии, предшествовавшей текущей загрузке | Постмортем: исследование последних записей лога перед внезапным выключением или падением хоста (`sudo journalctl -b -1 -n 50`) |
| `sudo journalctl --disk-usage` | Обслуживание | Показывает суммарный объем диска, занятый архивами журнала | Контроль ресурсов: проверка размера хранилища systemd-journald для предотвращения переполнения диска (`sudo journalctl --disk-usage`) |
| `sudo journalctl --vacuum-size=<size>` | Обслуживание | Удаляет старые архивные файлы для удержания размера в заданном лимите | Очистка диска: безопасное освобождение места ограничением максимального объема архивов журнала (`sudo journalctl --vacuum-size=100M`) |

## 3. Анализ сетевых пакетов (`tcpdump`)

| Команда | Категория | Описание | Применение в продакшене и DevOps |
| :--- | :--- | :--- | :--- |
| `sudo tcpdump -i <interface>` | Захват | Перехватывает сетевые пакеты на указанном интерфейсе | Локализация трафика: захват сетевого трафика на основном физическом или виртуальном интерфейсе (`sudo tcpdump -i eth0`) |
| `sudo tcpdump -i any` | Захват | Перехватывает пакеты на всех активных сетевых интерфейсах хоста | Общесистемный захват: анализ трафика на всех интерфейсах, включая петлевой loopback и виртуальные мосты (`sudo tcpdump -i any`) |
| `sudo tcpdump -i any -n` | Производительность | Отключает обратное преобразование IP-адресов в доменные имена | Захват под нагрузкой: подавление запросов DNS для предотвращения потери пакетов при высокой нагрузке (`sudo tcpdump -i any -n`) |
| `sudo tcpdump -i any -nn` | Производительность | Отключает преобразование IP-адресов в имена хостов и номеров портов в имена служб | Числовой вывод: отображение строгих числовых IP и портов для точного анализа сетевых сокетов (`sudo tcpdump -i any -nn`) |
| `sudo tcpdump -i any -A` | Полезная нагрузка | Декодирует и выводит байты полезной нагрузки пакета в виде ASCII-текста | Проверка HTTP: анализ незашифрованных HTTP-запросов, заголовков и тел API в канале связи (`sudo tcpdump -i any -A port 80`) |
| `sudo tcpdump -i any -X` | Полезная нагрузка | Выводит заголовки и тело пакета одновременно в шестнадцатеричном виде и ASCII | Низкоуровневая отладка: анализ бинарных структур протоколов и байтовых смещений (`sudo tcpdump -i any -X port 80`) |
| `sudo tcpdump -i any -e` | Канальный уровень | Выводит заголовки канального уровня Ethernet с MAC-адресами | Аудит шлюзов: проверка аппаратных MAC-адресов источника и назначения в локальном сегменте (`sudo tcpdump -i any -e port 80`) |
| `sudo tcpdump -i any -c <count>` | Ограничитель | Завершает захват после перехвата точного количества пакетов | Скрипты автоматизации: захват фиксированной выборки из 10 пакетов для проверки и автоматический выход (`sudo tcpdump -i any -c 10 port 80`) |
| `sudo tcpdump -i any -w <file>` | Сохранение | Записывает бинарный поток пакетов в файл формата pcap для Wireshark | Эскалация инцидента: сохранение дампа трассировки для передачи инженерам по сетевой безопасности (`sudo tcpdump -i any -w trace.pcap port 80`) |
| `tcpdump -nn -r <file.pcap>` | Воспроизведение | Читает, фильтрует и декодирует ранее сохраненный бинарный pcap-файл | Офлайн-анализ: исследование сохраненных дампов сетевого трафика с применением BPF-фильтров (`tcpdump -nn -r trace.pcap`) |
| `sudo tcpdump -i any port 53` | BPF-фильтр | Захватывает запросы и ответы службы DNS на 53-м порту | Отладка DNS: выявление сетевых задержек при резолвинге, сбоев разрешения имен или ответов NXDOMAIN (`sudo tcpdump -i any -nn port 53`) |
| `sudo tcpdump -i any port <port>` | BPF-фильтр | Перехватывает пакеты, где порт источника или назначения совпадает с указанным | Сниффинг сервиса: изоляция сетевого трафика конкретной базы данных или веб-приложения (`sudo tcpdump -i any port 443`) |
| `sudo tcpdump -i any host <ip>` | BPF-фильтр | Захватывает пакеты, отправленные на указанный IP или полученные с него | Трассировка хоста: мониторинг сетевого взаимодействия с конкретным внутренним микросервисом (`sudo tcpdump -i any host 10.0.0.5`) |
| `sudo tcpdump -i any "tcp and not port 22"` | BPF-фильтр | Перехватывает TCP-трафик, исключая административный SSH | Безопасность терминала: анализ прикладного TCP-трафика без засорения вывода пакетами текущей SSH-сессии (`sudo tcpdump -i any "tcp and not port 22"`) |
| `sudo tcpdump -i any "tcp[tcpflags] & tcp-syn != 0"` | Флаги TCP | Изолирует пакеты с установленным флагом SYN (начало соединения) | Обнаружение сканирования: фиксация попыток инициализации новых TCP-сессий по разным портам (`sudo tcpdump -i any "tcp[tcpflags] & tcp-syn != 0"`) |
| `sudo tcpdump -i any "tcp[tcpflags] & tcp-rst != 0"` | Флаги TCP | Изолирует пакеты с установленным флагом RST (сброс соединения) | Диагностика сбоев: обнаружение отклоненных соединений или принудительно разорванных сокетов (`sudo tcpdump -i any "tcp[tcpflags] & tcp-rst != 0"`) |

## 4. Вспомогательные диагностические команды

| Команда | Инструмент | Описание | Применение в продакшене и DevOps |
| :--- | :--- | :--- | :--- |
| `hostname -I` | Сеть | Выводит все IP-адреса, назначенные сетевым интерфейсам хоста | Обнаружение IP: определение внутренних IP-адресов на активных сетевых интерфейсах сервера (`hostname -I`) |
| `ip route show default` | Сеть | Определяет IP-адрес шлюза по умолчанию (адрес хостового моста) | Аудит виртуализации: нахождение адреса Hyper-V vSwitch или сетевого моста Multipass (`ip route show default`) |
| `sudo ss -tunlp` | Сокеты | Показывает открытые TCP и UDP сокеты с идентификаторами процессов (PID) | Аудит состояния сокетов: проверка привязки службы к требуемому порту и сетевому адресу (`sudo ss -tunlp \| grep :80`) |
| `curl -I <url>` | HTTP-клиент | Запрашивает HTTP-заголовки для проверки доступности веб-сервиса | Тестирование клиентом: проверка эндпоинта снаружи на предмет тайм-аутов, отказов подключения или кодов ответа (`curl -I http://172.28.16.50`) |
| `nc -zv <host> <port>` | Транспорт | Проверяет доступность TCP-порта без передачи прикладных данных | Тестирование периметра: проверка открытости порта на удаленном фаерволе без прикладного рукопожатия (`nc -zv 172.28.16.50 80`) |
